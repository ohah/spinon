# PR #522 runtime 이미지 링크 수정 검토 (30개 관점)

Rspress가 README의 PNG 경로를 패키지 이름으로 해석해 빌드가 실패했다. 두 링크에 명시적 `./`를 추가하는 변경을 검토했다.

| # | 실패 관점 | 확인 | 결과 |
| ---: | --- | --- | --- |
| 1 | 빌드 오류 원인 | Rspress가 runtime README의 두 PNG 경로를 모듈 요청으로 처리했다. | pass55 빌드 로그에서 확인했다. |
| 2 | 상대 이미지 표기 | 두 Markdown 이미지 경로가 모두 ./로 시작하는지 확인했다. | 명시적 상대 경로 접두사를 추가했다. |
| 3 | Android 이미지 대상 | Android PNG가 README 디렉터리 기준으로 해석되는지 확인했다. | 원본 이미지 파일이 존재한다. |
| 4 | iOS 이미지 대상 | iOS PNG가 README 디렉터리 기준으로 해석되는지 확인했다. | 원본 이미지 파일이 존재한다. |
| 5 | 대체 텍스트 | Android·iOS alt 텍스트가 보존되는지 확인했다. | 경로 접두사만 변경했다. |
| 6 | 이미지 바이트 | 스크린샷 파일 자체가 바뀌지 않았는지 확인했다. | 수정 대상은 README뿐이다. |
| 7 | 이미지 형식 | 두 경로가 .png 확장자를 유지하는지 확인했다. | 정규 PNG 파일을 참조한다. |
| 8 | 변경 범위 | 두 Markdown 이미지 링크 외 README 내용이 바뀌지 않았는지 확인했다. | 한 줄의 링크 두 곳만 수정했다. |
| 9 | 원본 문서 | 생성된 미리보기만 바꾸지 않고 저장소 원본을 수정했는지 확인했다. | 원본 runtime README에 수정이 있다. |
| 10 | 경로 기준 | 이미지 파일이 README의 증거 디렉터리 아래에 있는지 확인했다. | 링크가 디렉터리 밖으로 벗어나지 않는다. |
| 11 | 내부 별칭 | 선택 사이트의 internal·spec/internal 별칭에서도 상대 경로가 유지되는지 확인했다. | 각 별칭에 같은 하위 구조를 복사한다. |
| 12 | 공개 별칭 | public/internal 별칭에서도 상대 경로가 유지되는지 확인했다. | 공개 별칭에도 같은 경로가 존재한다. |
| 13 | MDX 번들러 | 명시적 ./가 이미지 요청을 상대 파일 import로 만드는지 확인했다. | 패키지 이름으로 해석되는 오류를 피한다. |
| 14 | 전역 resolver | Rspress/Rspack 전역 resolver 설정을 바꾸지 않았는지 확인했다. | 문제 링크만 국소적으로 수정했다. |
| 15 | 의존성 | package manifest와 lockfile을 바꾸지 않았는지 확인했다. | Rspress 2.0.22 고정을 유지한다. |
| 16 | 런타임 코드 | Rust·Swift·Kotlin·C·renderer 코드를 수정하지 않았는지 확인했다. | 문서 전용 변경이다. |
| 17 | Scene 주장 | scene 결과와 네 고정 장면 범위가 유지되는지 확인했다. | runtime 근거에 있던 수치를 바꾸지 않았다. |
| 18 | Android 환경 | Android 검증을 API 37 ARM64 AVD로 유지했는지 확인했다. | 실기기 표현을 추가하지 않았다. |
| 19 | iOS 환경 | iOS 검증을 iPhone 17 Pro/iOS 26.2 Simulator로 유지했는지 확인했다. | compositor 이후 결과로 확대하지 않았다. |
| 20 | PixelCopy 한계 | Android 표본을 PixelCopy 근거 범위 안에서 표현했는지 확인했다. | 화면 전체 적합성 주장으로 확대하지 않았다. |
| 21 | Metal 한계 | iOS 표본이 제출 전 Metal drawable readback인지 유지했는지 확인했다. | compositor 이후 검증으로 표현하지 않았다. |
| 22 | Glyph 한계 | text glyph raster를 확인했다는 주장이 없는지 확인했다. | glyph pixel 미검증 설명을 보존했다. |
| 23 | Border 한계 | 표본을 전체 CSS border stroke 검증으로 확대하지 않았는지 확인했다. | border 전체 적합성 미검증을 보존했다. |
| 24 | CSS 범위 | 제한 fixture를 임의 CSS admission으로 표현하지 않았는지 확인했다. | 일반 CSS 지원 주장을 추가하지 않았다. |
| 25 | WPT 범위 | WPT 결과를 새로 주장하지 않았는지 확인했다. | 미검증 상태를 보존했다. |
| 26 | 진행률 | C11.4 미완료와 공식 77/213 상태를 바꾸지 않았는지 확인했다. | 상태 파일과 로드맵 카운터를 수정하지 않았다. |
| 27 | 계약 버전 | 내부 계약 0.1.0을 유지했는지 확인했다. | 버전 메타데이터 변경이 없다. |
| 28 | 경로 파일 존재 | 두 상대 경로가 실제 파일로 해석되는지 확인했다. | 두 PNG 모두 파일시스템에 있다. |
| 29 | 병합 소스 | 원본 README 수정이 PR을 통해 main에 들어가도록 구성했는지 확인했다. | 병합 뒤 main 기준으로 사이트를 다시 만든다. |
| 30 | 다른 기록 | README의 다른 장면 기록이 삭제되거나 바뀌지 않았는지 확인했다. | 이미지 링크 두 곳만 수정했다. |

두 경로가 증거 디렉터리의 원본 PNG를 가리킨다. 앱 동작과 상태 대장 값은 바뀌지 않았다.
