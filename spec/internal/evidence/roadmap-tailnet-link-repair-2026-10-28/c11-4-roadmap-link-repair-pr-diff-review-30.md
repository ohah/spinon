# C11.4 로드맵 링크 복구 PR 변경분 적대적 검토 30관점

대상 변경은 `spec/public/roadmap.html`의 #738 카드 링크와 `plan/c11-4-grid-track-sizing.md`의 요약 상태다. Tailnet 정적 미리보기에 로드맵 파일만 복사되어 새 상대 경로가 404였고, 계획 요약은 병합 후에도 계획 단계로 남아 있었다. 아래 검토는 서로 다른 경로·상태·증거 경계를 확인한다.

| # | 실패 가설 / 검증 관점 | 판정 |
|---:|---|---|
| 1 | 집중 계획 URL이 저장소의 실제 Markdown 파일을 가리키지 않는다. | GitHub `blob/main` 경로와 저장소 파일명을 대조한다. |
| 2 | 실행 근거 README 링크에서 증거 디렉터리 이름이 달라진다. | `c11-4-mixed-intrinsic-flex-fixed-runtime-2026-10-28/README.md`와 대조한다. |
| 3 | 검증 JSON 링크가 이전 visibility matrix를 가리킨다. | 파일명에 작업·날짜가 모두 포함되는지 확인한다. |
| 4 | archive 경계 링크가 HTML 변환본에 남아 있다. | 원본 `.md` 경로로 연결한다. |
| 5 | 구현/runtime 검토 링크가 다른 20관점 문서로 바뀐다. | 파일명과 증거 디렉터리를 각각 대조한다. |
| 6 | PR diff 검토 링크가 계획 검토 문서로 오인된다. | 구현 `visibility-hidden-pr-diff-review-30.md`를 지정한다. |
| 7 | 병합 후 문서 검토 링크가 로컬 Tailnet 경로에 의존한다. | GitHub 원본 문서 주소로 바꾼다. |
| 8 | Android 화면 링크가 PR head의 rebase 전 SHA에 의존한다. | PR #738의 최종 merge SHA를 raw URL에 고정한다. |
| 9 | iOS 화면 링크가 Android 이미지를 가리킨다. | 파일명과 run 디렉터리를 기기별로 대조한다. |
| 10 | 화면 URL은 열리지만 이미지 바이트가 다른 run 산출물이다. | merge SHA와 두 run 경로가 일치하는지 확인한다. |
| 11 | PNG를 `blob` URL로 연결해 브라우저에서 이미지 대신 코드 뷰가 열린다. | `raw.githubusercontent.com` 형식을 사용한다. |
| 12 | Markdown/JSON 문서를 Tailnet 미리보기에 다시 복사해야만 열 수 있다. | GitHub 원본을 직접 연결해 미리보기 배포 파일 의존성을 제거한다. |
| 13 | GitHub 문서 주소에 저장소 소유자나 저장소 이름 오타가 있다. | 모든 링크의 `ohah/spinon`을 확인한다. |
| 14 | `main` 브랜치 링크가 이번 문서 PR 병합 후 최신 내용을 가리키지 않는다. | 코드 문서는 병합 후 `main`에서 읽도록 한다. |
| 15 | immutable PNG 주소가 문서 브랜치 SHA로 바뀌어 산출물을 잃는다. | 구현이 병합된 `bf4ab21eebc2f3739a7ae61de6511b92733b9464`를 고정한다. |
| 16 | 공식 상태 링크가 Tailnet의 누락된 `STATUS.html`을 계속 참조한다. | `spec/STATUS.md` 저장소 경로로 바꾼다. |
| 17 | 공식 상태 anchor가 제거되거나 인코딩되어 링크가 무효가 된다. | 기존 `#css-구현-체크리스트` fragment를 유지한다. |
| 18 | 같은 페이지 카드에서 일부 링크만 바뀌어 상대 경로 404가 남는다. | 계획·근거·JSON·리뷰·이미지·상태 링크를 모두 분류한다. |
| 19 | 다른 카드의 기존 링크까지 무관하게 변경된다. | 변경을 PR #738 카드 한 줄로 제한한다. |
| 20 | #738의 PR 번호·merge SHA·시각이 문서 수정 중 바뀐다. | 링크 대상만 교체하고 식별 메타데이터는 보존한다. |
| 21 | Android/iOS 각각 14/14 결과가 다르게 서술된다. | 카드의 실행 횟수 문구를 수정하지 않는다. |
| 22 | 표면 표본 설명을 전체 GPU·compositor 검증으로 확대한다. | PixelCopy·Metal 표본만 기존 범위로 둔다. |
| 23 | 비어 있는 GitHub check rollup을 CI 통과로 오표기한다. | 카드와 계획 요약 모두 check rollup이 비었다고 적는다. |
| 24 | 임의 CSS·전체 WPT·실기기 등 미검증 범위가 사라진다. | 로드맵 카드의 기존 제한 문장을 유지한다. |
| 25 | 상위 C11.4가 이 slice로 완료 처리된다. | 상위 미완료 상태를 유지한다. |
| 26 | 공식 완료 수가 72/213에서 증가한다. | 두 문서 모두 공식 `72/213`을 유지한다. |
| 27 | 계획 인덱스가 #738을 아직 미병합으로 표시한다. | 요약을 #738 Rebase and merge 기록으로 갱신한다. |
| 28 | 계획 인덱스의 Android/iOS 검증 수가 최종 14/14와 다르다. | 병합 증거와 각 14/14를 적는다. |
| 29 | 사전 비교와 계획 단계 기록이 사라져 구현 판정의 출처가 끊긴다. | #737 계획 PR 및 precomparison 링크를 보존한다. |
| 30 | Tailnet에서 HTML만 있어야 로드맵 내부 근거 링크가 열린다. | GitHub 문서·JSON·raw 이미지로 향하게 하고 배포 의존성을 없앤다. |

실제 브라우저 URL 응답과 Tailnet 화면은 PR 병합·단일 파일 동기화 뒤 별도 기록한다. 이 문서는 로드맵 링크 수정만 검토하며, runtime 동작을 새로 검증했다고 주장하지 않는다.
