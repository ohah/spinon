# Tailnet 미리보기 동기화 실패 관점 검토

| # | 실패 관점과 확인 | 결과 |
| --- | --- | --- |
| 1 | 공식 구현 상태가 동기화 때문에 바뀌지 않는가 — 현재 `STATUS.md`와 브라우저 DOM의 C11.4 체크를 대조했다. | C11.4 intrinsic track sizing 체크는 미완료다. |
| 2 | 로드맵 문구가 완료 집계를 부풀리지 않는가 — 로드맵 노트와 공식 대장을 비교했다. | 10-scene 실기기 부분 결과와 전체 Grid 미완료를 함께 표시한다. |
| 3 | PR 기준 커밋이 미리보기 소스의 부모인가 — PR #397 병합 SHA를 확인했다. | `24267943981a9c7dee693155efb8607bcf8e405c`를 기준으로 삼았다. |
| 4 | 선택 빌드가 오래된 상태·계획 파일을 참조하지 않는가 — 후보 root의 상태 대장·계획·로드맵을 현재 문서와 비교했다. | 네 입력이 최신 Tailnet 선택 root에 포함됐다. |
| 5 | 본문만 새롭고 hydration 청크는 오래된 조합인가 — 페이지를 같은 RSPress 출력에서 다시 만들고 브라우저에서 읽었다. | 한 빌드의 HTML·JavaScript 청크가 함께 반영됐다. |
| 6 | 전체 문서 메뉴가 부분 선택 때문에 사라지지 않는가 — C11.4 계획과 실기기 근거 페이지의 좌측 메뉴를 확인했다. | 계획 108개, 근거 페이지 95개 링크가 표시됐다. |
| 7 | 페이지가 참조하는 새 정적 자산이 빠졌는가 — 선택 빌드 파일 집합과 외부 응답을 대조했다. | 선택 파일 1,720개가 모두 응답하고 해시가 일치한다. |
| 8 | 사이트 base path가 Tailnet 하위 경로와 어긋나는가 — 렌더된 링크와 실 URL을 확인했다. | `/spinon/` 링크로 페이지·자산을 불러온다. |
| 9 | dead-link 검사 비활성화를 전체 저장소 검증 성공으로 오해하는가 — 선택 빌드 설정과 전체 docs 로그를 분리해 기록했다. | 전체 docs build의 기존 실패를 별도 한계로 남겼다. |
| 10 | dead-image 검사 비활성화가 무관한 사용자 설정을 바꾸는가 — 설정을 pass24 임시 config에만 적용했다. | 프로젝트 RSPress config와 패키지 설정은 수정하지 않았다. |
| 11 | Shiki `rust,ignore` 문제를 선택 빌드 성공으로 숨기는가 — 전체 docs 실패 로그를 검토했다. | 전체 빌드는 실패로 기록하고 선택 빌드 성공과 분리했다. |
| 12 | 중복 status·plan 경로가 서로 다른 내용을 제공하는가 — 후보 route와 브라우저에서 상태·계획 페이지를 확인했다. | 양쪽 공개 경로가 동일한 현재 문서를 렌더링한다. |
| 13 | 오래된 파일 삭제로 이전 링크나 캐시가 깨지는가 — 사전 비교와 동기화 결과의 delete 항목을 확인했다. | 파일 삭제는 0건이다. |
| 14 | 원본 경로가 root 밖으로 벗어나는가 — 동기화 스크립트가 root-relative 경로만 나열하도록 확인했다. | 선택 root 파일만 대상으로 삼는다. |
| 15 | 심볼릭 링크가 대상 root 밖을 가리키는가 — 소스와 대상 구성요소에서 symlink를 거부한다. | 사전 비교에서 링크 탈출 경로가 발견되지 않았다. |
| 16 | 빌드 파일이 사전 비교 뒤 바뀌는가 — 복사 전에 전체 source 집합·크기·SHA를 다시 비교했다. | 복사 및 최종 검증에서 source manifest가 유지됐다. |
| 17 | Tailnet 기존 파일이 사전 비교 뒤 변하는가 — 기존 파일의 크기·SHA를 사전값과 대조한 뒤 교체했다. | 동기화 스크립트가 일치하지 않는 대상이면 중단한다. |
| 18 | 백업 경로가 다른 작업의 백업을 덮는가 — pass24 전용 경로와 기존 파일 재사용 규칙을 확인했다. | 새 백업 경로를 쓰고, 재개 때 기존 백업도 원본 해시와 맞는 경우만 재사용한다. |
| 19 | 교체 전 원본 복구본이 불완전한가 — 원본 91개의 바이트 수와 SHA-256을 다시 계산했다. | 백업 91/91 검증됐다. |
| 20 | 파일 일부 쓰기 도중 서버가 잘린 내용을 제공하는가 — 임시 파일을 같은 디렉터리에 fsync하고 rename한다. | 대상 파일은 검증 뒤 원자 교체됐다. |
| 21 | 열려 있는 파일을 무시하고 덮어써 데이터가 손상되는가 — 교체 직전 `lsof` PID와 서버 소켓을 검사했다. | 한 핸들은 대기 소켓만 가진 Tailnet 서버 PID 1191의 것이었고 원본 백업 뒤 원자 교체했다. |
| 22 | Tailnet 서버가 업데이트 중 종료되는가 — 교체 전후 PID와 8768 listening socket을 확인했다. | 같은 PID 1191이 계속 수신한다. |
| 23 | 부분 복사가 나중에 혼합된 후보를 남기는가 — 재개 전 새 사전 비교를 생성하고 복사 후 전체 대상 hash를 확인했다. | 최종 대상 1,720/1,720이 단일 후보 빌드와 일치한다. |
| 24 | Tailnet reverse proxy가 로컬 대상과 다른 본문을 반환하는가 — Tailnet HTTPS에서 모든 선택 파일을 다시 내려받았다. | HTTP 200·바이트 수·SHA-256 모두 1,720/1,720 일치한다. |
| 25 | 새 route JavaScript가 404 또는 stale chunk가 되는가 — 새 사이트 전체 파일 경로의 외부 응답을 확인했다. | 선택 파일 전체가 200이며 본문 SHA가 후보와 같다. |
| 26 | 사람 화면이 CLI 결과와 다른가 — Agent Browser에서 Tailnet 실제 주소를 열었다. | 로드맵·상태·계획·근거 화면을 렌더링했다. |
| 27 | 로드맵에 잘못된 C11.4 완료 표시가 뜨는가 — 새 note의 실행 요약과 공식 status checkbox를 각각 읽었다. | 부분 실기기 결과를 표시하고 체크는 미완료다. |
| 28 | 근거 이미지가 깨졌는데 링크만 보이는가 — 근거 페이지의 이미지 `complete`와 `naturalWidth`를 확인했다. | 로고와 Samsung 캡처 두 장이 모두 로드됐다. |
| 29 | 브라우저 콘솔·페이지 오류를 숨기는가 — Agent Browser errors/console을 비우고 마지막 상태를 확인했다. | 오류 출력이 없었다. |
| 30 | 문서 배포 경로나 브라우저 프로세스가 불필요하게 남는가 — Pages workflow 미실행, 세션 종료, 활성 세션 목록을 확인했다. | Pages 변경 없음, Agent Browser 세션 없음, Tailnet 서버만 유지한다. |
