# C10.3.4 계획 문서 동기화 PR 검토

## 범위

이 PR은 C10.3.4 baseline 계획 검토 기록을 추가하고, 이미 병합된 C10.3.3 PR #122의 상태를 전용 계획·내부 계약·상태 대장·작업 미리보기에 맞춘다. 런타임 구현을 추가하거나 C10.3.4 완료를 주장하지 않는다.

## 별도의 실패 관점 20개

| # | 공격 관점 | 확인 결과 |
|---:|---|---|
| 1 | C10.3.3이 공식 체크에서 계속 미완료로 남는가 | 상태 대장 체크와 PR #122 병합 표기를 함께 고쳤다. |
| 2 | 병합되지 않은 PR 번호를 완료 근거로 쓰는가 | GitHub가 반환한 PR #122의 실제 병합 상태와 merge commit을 확인했다. |
| 3 | 부모 C10.3을 하위 단계와 함께 완료 처리하는가 | C10.3.4·3.5와 C15 연결이 남아 parent 체크를 유지한다. |
| 4 | 내부 계약 0052의 버전 숫자를 작업 상태 변경으로 올리는가 | 내부 계약은 `0.1.0`으로 유지한다. |
| 5 | 0052가 “PR 검토 대기”라고 잘못 표기되는가 | 현재 병합된 PR #122를 문서 헤더에 기록한다. |
| 6 | 계획 문서 상대 링크가 존재하지 않는 파일을 가리키는가 | 계획 검토 근거 파일을 추가하고 링크 대상을 확인했다. |
| 7 | 상태 대장과 계획표가 C10.3.4 진행 상태에서 갈리는가 | 둘 다 “계획 검토 반영, 구현 전”으로 표기한다. |
| 8 | 공개 작업 보드가 C10.3.3을 다음 작업으로 보여 주는가 | 다음 순서를 C10.3.4로 바꾸고 진행 중은 비워 두었다. |
| 9 | 작업 보드가 아직 시작하지 않은 코드를 진행 중으로 주장하는가 | hero와 보드 모두 구현 전 상태를 분명히 한다. |
| 10 | PR #122의 고정 Chrome 수치를 새 baseline 검증으로 오인하는가 | C10.3.3 evidence와 C10.3.4 plan review를 별도 경로로 둔다. |
| 11 | C10.3.4에서 텍스트 baseline 지원까지 완료한 듯 보이는가 | 텍스트는 C15 선행으로 명시하고 구현 전 체크를 유지한다. |
| 12 | `align-content:first baseline`을 Flex 줄끼리 맞추는 값으로 기록하는가 | item content-alignment 경계와 line distribution을 구분한다. |
| 13 | `align-content:last baseline`이 고정 Chrome에서 지원된다고 주장하는가 | Chrome 관찰상 invalid인 값을 성공 경로로 선언하지 않는다. |
| 14 | first와 last baseline을 동일 키워드로 축약하는가 | 계획상 distinct variant와 각각의 비교 fixture를 요구한다. |
| 15 | Taffy가 last baseline을 제공한다고 잘못 전제하는가 | 잠긴 0.14.0 Flex 출력의 first-only 경계를 기록한다. |
| 16 | C07.2의 border paint를 baseline 기하 근거로 사용하는가 | border used geometry와 paint 범위를 분리한다. |
| 17 | 런타임이나 WPT를 실행하지 않았는데 통과했다고 적는가 | 문서는 계획 검토이며 WPT 미실행임을 명시한다. |
| 18 | WPT 제외 범위를 완료 범위로 확대하는가 | 고정 fixture 한정과 미실행 WPT를 함께 남긴다. |
| 19 | 로드맵 문서 갱신이 GitHub Pages 배포를 실행하는가 | 저장소 파일만 수정하고 Pages workflow는 실행하지 않는다. |
| 20 | 주변 미추적 증거나 spike를 이 PR에 실수로 포함하는가 | stage 목록을 PR 네 문서와 이 검토 기록으로 제한한다. |

## 결과

계획 검토와 문서 상태가 서로 일치한다. C10.3.4 기능 구현, Rust·CSS 테스트, Android 실기기 확인은 이 PR에서 수행하지 않았고 완료로 표시하지 않는다.
