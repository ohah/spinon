# C09.1 병합 후 상태·명세 동기화 검토

## 범위

- 대상: PR #107 병합 뒤 `spec/STATUS.md`, 내부 계약 `0047`, 계획, 인덱스와 실행 근거 사이의 상태 정합성.
- 코드·fixture·기준 수치는 PR #107의 병합 결과와 기존 구현 근거를 기준으로 대조했다.
- C09.1만 완료로 표시하고 C09 상위 및 C09.2–C09.4를 미완료로 유지한다.

## 서로 다른 실패 관점

| # | 실패 관점 | 확인 결과 |
| --- | --- | --- |
| 1 | C09.1 완료가 C09 상위 완료로 승격되는가 | 상위 C09 체크는 미완료이며 설명에 C09.2–C09.4 잔여 범위를 남겼다. |
| 2 | C09.2 수직 margin collapse가 완료로 오인되는가 | 상태 대장·계획에서 미구현이다. |
| 3 | C09.3 `flow-root` BFC가 C09.1에 포함되는가 | 상태 대장·계획에서 별도 미구현 하위 항목이다. |
| 4 | C09.4 shrink-to-fit 선행 의존이 사라지는가 | 미구현이며 C12/C14/C15/C26 의존성을 유지한다. |
| 5 | C09 전체 23개 case·76개 node와 C09.1 10개 case·30개 node가 섞이는가 | 문서마다 전체 기준과 완료 subset을 구분한다. |
| 6 | Chromium oracle 버전이 달라지는가 | Chrome 154.0.8037.98 및 고정 revision을 기존 근거와 맞췄다. |
| 7 | DPR 1·2가 완료 조건에서 빠지는가 | 상태·계획·근거가 DPR 1·2 비교를 유지한다. |
| 8 | node frame 오차 기준이 문서마다 달라지는가 | 0.5 CSS px 기준을 유지한다. |
| 9 | Android API와 기기 종류가 뒤바뀌는가 | Android API 37 ARM64 emulator로 기록한다. |
| 10 | iOS simulator 결과를 실기기 결과로 과장하는가 | iPhone 17 Pro / iOS 26.2 Simulator로 한정했다. |
| 11 | software renderer를 hardware GPU 성능으로 오인하는가 | Android ANGLE/SwiftShader 제한과 성능 비주장을 유지한다. |
| 12 | V8→Stylo→Taffy→WGPU 경로를 네이티브 뷰로 잘못 부르는가 | 문서에서 실제 runtime 경로를 그대로 명시한다. |
| 13 | `border-width` 계산을 border 선 표시 완료로 오인하는가 | 내부 계약과 PR #107 근거에서 geometry와 C22 선 paint를 분리한다. |
| 14 | at-rule이 C09.1 지원으로 읽히는가 | 현재 profile에서 at-rule 자체가 지원 밖이며 실패한다고 명시한다. |
| 15 | CSS source preflight가 cascade 적용 selector만 검사한다고 오인되는가 | authored source 전체 검사 한계와 cascade winner 비동등성을 유지한다. |
| 16 | 중첩 CSS 깊이 제한이 누락되는가 | at-rule·CSS 중첩 규칙 64단계 제한을 내부 계약에 유지한다. |
| 17 | 내부 fixture 완료가 공개 API 지원으로 확대되는가 | `0047`과 README에서 공개 API가 아님을 유지한다. |
| 18 | 계약 숫자 버전이 올라가는가 | 출시 전 숫자 버전 `0.1.0`을 유지한다. |
| 19 | 계획·내부 계약·내부 인덱스의 PR 상태가 서로 다른가 | 세 문서가 PR #107 병합 상태와 C09 잔여 범위를 일치시킨다. |
| 20 | 병합 후 캡처·로그 링크가 끊기거나 이전 파일로 바뀌는가 | Android/iOS PNG·로그와 C09.1 실행 근거의 상대 경로가 존재한다. |

## 결과

상태 대장의 C09.1 하위 체크만 완료로 표시했다. 부모 C09와 미구현 하위 항목은 미완료로 유지했다. 내부 계약, 계획, 인덱스와 기존 실행 근거의 링크·범위가 같은 병합 상태를 가리킨다.
