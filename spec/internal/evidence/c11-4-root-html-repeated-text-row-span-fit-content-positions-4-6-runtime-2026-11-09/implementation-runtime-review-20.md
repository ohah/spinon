# 구현·런타임 적대적 검토 20개

검토 범위는 현재 C11.4 bounded row-span slice의 Taffy track sizing 변경, Root HTML admission·frame normalization, 4,320-scene 비교와 거부/복구 검사다. 계획 검토와 겹치지 않도록 코드 경계와 실행 실패 경로를 새로 확인했다. 각 항목은 서로 다른 결함 경로를 다룬다.

1. **공간 기여가 0인 span 그룹의 경계 커밋** — 기존 early-return은 affected track의 계획 증가가 0일 때 infinite growth limit를 그대로 남겼다. 0 공간이어도 affected marker를 기록하고 그룹 뒤에서 `base_size + 0`을 반영하도록 바꿨다. 설명 주석도 실제 분기와 맞게 고쳤다. [Taffy §11.5.1 helper](../../../../vendor/taffy/src/compute/grid/track_sizing.rs) · [W3C 2025 CRD §11.5.1](https://www.w3.org/TR/2025/CRD-css-grid-1-20250326/#extra-space).
2. **span 길이별 순차 처리** — span group마다 intrinsic-minimum/max-content-maximum growth-limit 분배 뒤 flush가 호출되는지 확인했다. 다음 길이 그룹은 직전 그룹의 업데이트된 growth limit를 읽는다. [Taffy `resolve_intrinsic_track_sizes`](../../../../vendor/taffy/src/compute/grid/track_sizing.rs) · 4,320 scene pass.
3. **무한 growth limit 초기 크기** — 처음 무한이던 affected track은 flush 시 base size와 계획 증가의 합으로 바뀐다. 무한 상태 그대로 다음 그룹으로 흘러가거나 planned increase를 growth limit에 더하지 않는 경로를 막는다. [Taffy `flush_planned_growth_limit_increases`](../../../../vendor/taffy/src/compute/grid/track_sizing.rs) · 127 Grid track-sizing tests pass.
4. **infinitely-growable 단계 범위** — flag는 flush 직전 growth limit가 무한이었고 호출 단계가 해당 flag를 설정하는 단계일 때만 true다. 유한 growth limit는 우연히 다음 그룹에서 무제한으로 취급되지 않는다. [Taffy flush 및 Step 5/6 호출부](../../../../vendor/taffy/src/compute/grid/track_sizing.rs) · 4,320 scene와 127 tests pass.
5. **scratch state 재사용** — 새 `growth_limit_was_affected`는 track 초기화와 매 flush에서 모두 초기화된다. 이전 sizing pass 또는 span group의 marker가 다음 축·그룹으로 번지지 않는다. [GridTrack 초기화](../../../../vendor/taffy/src/compute/grid/types/grid_track.rs) · [Taffy initialize/flush](../../../../vendor/taffy/src/compute/grid/track_sizing.rs).
6. **비대상 track의 상태 오염** — `flush`는 affected가 아닌 track의 infinitely-growable flag를 false로 만들고 planned increase도 비운다. 분배 closure 밖의 track이 stale state로 다음 공간 분배에 들어가지 않는다. [Taffy flush/distribute](../../../../vendor/taffy/src/compute/grid/track_sizing.rs) · 127 tests pass.
7. **0·음수 남은 공간** — 남은 공간은 0으로 바닥 제한되고 zero-extra 분배는 track 크기를 키우지 않으면서 해당 그룹 경계만 기록한다. 0px/0% cap scene과 regression matrix가 통과했다. [Taffy `extra_space`](../../../../vendor/taffy/src/compute/grid/track_sizing.rs) · [4,320 matrix log](./checks/matrix-positions-4-6.log).
8. **fit-content cap의 상한** — 첫 분배와 beyond-limit 분배 모두 fit-content limit 함수를 적용한다. cap 0px/0%/10px/20px/20%/120%와 후행 track 순서 30개에서 Chrome used rows가 일치했다. [Taffy `distribute_space_up_to_limits`](../../../../vendor/taffy/src/compute/grid/track_sizing.rs) · [Chrome capture](../c11-4-root-html-repeated-text-row-span-fit-content-positions-4-6-precomparison-2026-11-09/README.md).
9. **유연 track 경로 분리** — growth-limit span 분배는 `!is_flex` 경로에서만 실행된다. 이 변경이 flex-spanning 단계에 intrinsic-max 처리나 flag 변화를 추가하지 않는다. [Taffy `resolve_intrinsic_track_sizes`](../../../../vendor/taffy/src/compute/grid/track_sizing.rs) · 127 tests pass.
10. **양의 implicit row 개수** — layout admission은 3-row 회귀 topology와 정확히 6-row가 되는 두 topology만 허용한다. 여섯 행은 line 2–8을 포함하는 span 2/3 배치에서 생성되며 다른 조합은 통과하지 않는다. [layout topology recognizer](../../../../crates/spinon-layout/src/grid/root_html_fit_content_auto_rows/repeated_text/span.rs).
11. **중복·누락·교차 topology 배치** — topology recognizer는 expected placement multiset의 정확한 길이와 각 항목 1회를 요구한다. 추가 또는 누락된 배치가 들어가면 supported row count를 반환하지 않는다. [style topology recognizer](../../../../crates/spinon-style-to-layout/src/projection/style_values/root_html_fit_content_auto_rows/validation_helpers.rs) · [rejection/recovery tests](../../../../crates/spinon-runtime/src/session/tests/root_html_grid_fit_content_auto_rows/later_fit_content_row_span/positions_4_6/rejections.rs).
12. **fit-content 위치의 인덱스 기준** — computed track list의 zero-based 위치에 1을 더해 authored 1-based 위치로 바꾸고 6-row topology에서 4–6만 admission한다. 1–3은 실패하며 4·5·6은 각 1,440 scene으로 모두 통과했다. [profile gate](../../../../crates/spinon-layout/src/grid/root_html_fit_content_auto_rows/profiles.rs) · [matrix log](./checks/matrix-positions-4-6.log) · [1–3 regression](./checks/matrix-positions-1-3.log).
13. **track list와 cap 문법** — six-member list는 min-content 2개, max-content 2개, auto 1개, fit-content 1개를 요구하고 cap은 유한한 0 이상 px/percentage만 받는다. 중복 fit, 잘못된 수, 비정상 cap은 후보에서 제외된다. [layout profile](../../../../crates/spinon-layout/src/grid/root_html_fit_content_auto_rows/profiles.rs) · [style profile](../../../../crates/spinon-style-to-layout/src/projection/style_values/grid_values.rs).
14. **방향·writing context** — review에서 row-span profile의 style admission이 Grid와 각 item의 writing context를 명시하지 않는 것을 발견했다. Grid 및 item의 LTR·horizontal 조건을 추가했고, Grid/item RTL 변형은 `grid-auto-rows` admission 오류로, vertical writing-mode는 현재 cascade 오류로 원자 거부되는 것을 검사했다. [admission helper](../../../../crates/spinon-style-to-layout/src/projection/style_values/root_html_fit_content_auto_rows/validation_helpers.rs) · [targeted rejection log](./checks/row-span-writing-context-rejections.log).
15. **Grid 기하·외곽 조건** — 기본 route의 40×220 grid, 40px column, 10px explicit row, 0 gap·margin·padding·border, visible overflow와 start/stretch alignment만 profile에 들어간다. 바깥 조건을 바꿔 normalization axis가 달라지는 scene은 받아들이지 않는다. [style validator](../../../../crates/spinon-style-to-layout/src/projection/style_values/root_html_fit_content_auto_rows.rs) · 4,320 matrix pass.
16. **텍스트 기여 안정성** — payload는 한 text source, ASCII 단어 grammar, 10px monospace와 고정 line-height 등으로 제한된다. 지원 범위 바깥의 inline run·다른 shaping·word-breaking 입력은 이 row-span profile을 통과하지 않는다. [text profile](../../../../crates/spinon-style-to-layout/src/projection/style_values/root_html_fit_content_auto_rows/repeated_text.rs) · [runtime text checker](../../../../crates/spinon-layout/src/grid/root_html_fit_content_auto_rows/repeated_text.rs).
17. **trace owner·revision 신뢰** — layout 결과 revision이 입력과 같고 대상 grid의 track trace가 정확히 하나여야 정규화한다. 누락·stale owner·중복 trace는 fail-closed다. [span normalizer](../../../../crates/spinon-layout/src/grid/root_html_fit_content_auto_rows/repeated_text/span.rs) · trace atomicity unit tests.
18. **trace topology 검증** — trace는 explicit row 1개, positive implicit row 6개, negative row/collapsed row 없음과 연속된 내부 track index를 만족해야 한다. row 크기는 finite·non-negative여야 한다. [final row trace guard](../../../../crates/spinon-layout/src/grid/root_html_fit_content_auto_rows/repeated_text/span.rs) · 7-track trace unit test.
19. **item·payload·text frame의 행 합 및 snapping** — item raw y/height가 실제 span한 row offset/합과 일치하는지 먼저 검사하고, Chrome capture의 Blink layout-unit rounding 후 item·flow descendants를 같은 delta로 갱신한다. 전체 matrix에서 semantic item/payload frames 및 text baseline이 일치했다. [normalizer](../../../../crates/spinon-layout/src/grid/root_html_fit_content_auto_rows/repeated_text/span.rs) · [matrix](../../../../crates/spinon-runtime/src/session/tests/root_html_grid_fit_content_auto_rows/later_fit_content_row_span/positions_4_6/matrix.rs).
20. **거부의 원자성·세션 복구** — 위치 1–3의 six-row 입력과 cross-topology 변경은 completed snapshot을 내지 않고 거부하며, 동일 세션에서 valid style로 돌아오면 새 revision으로 복구한다. axis/context 변형도 완료 결과를 게시하지 않는다. [rejection tests](../../../../crates/spinon-runtime/src/session/tests/root_html_grid_fit_content_auto_rows/later_fit_content_row_span/positions_4_6/rejections.rs) · [targeted log](./checks/row-span-writing-context-rejections.log).

## 검토 결과

검토 중 Taffy 분배 주석의 zero-space 설명을 실제 코드와 일치시켰고, row-span profile의 LTR·horizontal writing-context admission 누락을 수정했다. 영향받는 4,320 scene, 새 거부 검사, 기존 1–3/반복 text/row-span/auto-placement 회귀, Grid 127 tests와 Clippy가 통과했다. workspace/vendored rustfmt 및 `git diff --check`는 포맷 적용 뒤 각각 통과했다. 이 20관점 검토는 제품 코드의 동작 범위를 다루며 플랫폼 화면 패리티를 주장하지 않는다. 별도 런타임 기록에서 iOS 6 scene과 Android API 37.2 6 scene의 boot/layout-ready/draw-present 시각 smoke가 통과했다. `spinon-layout --lib` broad suite에는 기준 브랜치 여부가 확인되지 않은 실패 1건이 남는다.
