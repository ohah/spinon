# C12.1 병합 상태 동기화 검토

**범위:** PR #128 병합 뒤 공식 상태 대장, 내부 계약 인덱스, 단계 계획과 Tailnet 로드맵의 상태·범위 일치 여부. 이 검토는 기존 기능 실행 검증을 대체하지 않는다.

| # | 실패 관점 | 확인 결과 |
| ---: | --- | --- |
| 1 | PR이 실제 병합되지 않았는데 문서만 완료로 표시되는가 | GitHub에서 PR #128의 상태는 MERGED이며 병합 시각과 최종 커밋이 확인됐다. |
| 2 | rebase merge 뒤 머지 커밋이 생기거나 원격 기준 브랜치가 다르게 보이는가 | origin/main 최종 커밋은 부모가 하나인 선형 이력이다. |
| 3 | 병합된 C12.1이 공식 상태 대장에서 미완료로 남는가 | C12.1만 완료 체크하고 PR #128 병합을 명시했다. |
| 4 | 하위 하나의 병합이 C12 전체 완료로 확대되는가 | C12 parent는 미완료로 유지하고 고정·sticky·쌓임 단계를 남겼다. |
| 5 | C12.2가 구현 또는 지원 완료로 잘못 체크되는가 | C12.2는 미완료이며 다음 구현 단계로만 표시했다. |
| 6 | C12.2 시작 조건인 C07.1·C07.2가 빠졌는가 | 두 선행 단계 모두 공식 대장에서 완료 상태다. |
| 7 | Block containing block에 필요한 C09.1·C09.3가 미완료인데 진행하는가 | 두 단계가 완료로 기록되어 있고 C09 parent만 후속 C09.4 때문에 미완료다. |
| 8 | 상태 대장 기준일이 내용보다 오래된 채 남는가 | 기준일을 2026-10-11로 갱신했다. |
| 9 | 상태 동기화 때문에 내부 API 숫자 버전이 올라가는가 | 계약 0054와 상태 대장 모두 0.1.0을 유지한다. |
| 10 | 내부 구현을 공개 CSS/API 지원으로 과장하는가 | 계약과 상태 행에서 공개 API가 아님을 유지했다. |
| 11 | C12.1 범위가 absolute·fixed·sticky까지 넓어지는가 | static·relative와 물리 inset에 한정하고 후속 범위를 남겼다. |
| 12 | 기준 브라우저나 fixture가 달라져 수치가 재현되지 않는가 | Chromium 154와 12개 case·47개 식별 요소를 유지했다. |
| 13 | root viewport 크기 차이를 geometry 성공으로 섞는가 | 비교 근거는 viewport root의 width·height를 제외하고 나머지 47개 요소를 비교한다고 기록한다. |
| 14 | Android와 iOS 결과를 동일한 기기 조건인 것처럼 합치는가 | Android SM-S731N 실기기와 iOS 26.2 Simulator를 구분한다. |
| 15 | Android 시작 경합 수정이 빌드만 되고 실기기에서 재현되지 않는가 | 수정 후 앱 종료·재실행 3회의 로그와 WGPU 제출 근거를 연결했다. |
| 16 | 수정 전 최초 실패 로그가 보존된 것처럼 오해되는가 | 원본 실패 로그는 기기 ring buffer에서 밀려났다는 기존 한계를 유지한다. |
| 17 | 상태 전환 재시도와 초기 Surface 준비 대기가 서로 모순되는가 | 재시도는 후속 상태 전환 평가에 한정하고, 최초 fixture는 유효 크기 Surface 이후 시작하도록 설명했다. |
| 18 | 계획·계약 인덱스·상태 대장이 서로 다른 PR 상태를 보이는가 | 계획 헤더, 계약 0054, 내부 README, 상태 대장과 공개 로드맵에서 PR #128 병합 상태를 맞췄다. |
| 19 | 사용자가 보는 Tailnet 로드맵이 이전 PR 검토 문구나 이전 작업을 표시하는가 | 검토 시점 live route는 HTTP 200이며 agent-browser에서 PR #128 병합 문구와 C12.2 다음 카드를 확인했다. 칸반 완료 개수는 main의 공식 상태 파일을 읽으므로 이 상태 동기화 PR이 병합되기 전에는 이전 개수로 남는 점을 구분했다. |
| 20 | 전체 문서 빌드 실패를 이번 수정 오류로 숨기거나 성공으로 주장하는가 | 기본 빌드는 저장소의 다수 문서에서 죽은 링크 오류를 보고했다(C06·R05 근거 페이지 등). Tailnet 전용 빌드는 링크 검사 비활성 설정으로 성공했으며 기본 전체 문서 빌드 통과라고 주장하지 않는다. |

## 범위

검토 시점의 상태와 관찰 내용을 기록했다. 기본 RSPress 빌드의 저장소 전반 죽은 링크 오류는 이 동기화 변경에 포함하지 않았다.
