# 0059 · C11 Grid 레이아웃 내부 계약

**문서 ID:** `0059` · **내부 숫자 버전:** `0.1.0` 고정 · **상태:** C11.1·C11.2.1은 `origin/main`에 통합; C11.2.2·C11.2.3 제한 profile 및 지정 검증 완료; C11.3.1 제한 profile 검증 완료; C11.3.2 named-line 제한 profile 지정 검증 완료; C11.3.3 sparse area projection/resolution 후보 구현은 PR #152로 2026-10-14 Rebase 병합, Android API 37 AVD 26 scene·65 node matrix 및 iOS Simulator 전체 26 scene 행렬 검증; 2026-10-21 존재하지 않는 area 이름의 trailing implicit named-line 후속은 PR #393로 제출 · **Android:** C11.2.2·C11.2.3 SM-S731N 실기기 geometry/PixelCopy 행렬 통과; C11.3.2 사용자 승인 API 37 AVD gate 통과; C11.3.3 Android API 37 AVD PixelCopy 2/2 및 Android 16/API 36 SM-S731N 실기기 26-scene geometry·overflow PixelCopy 검증(ANGLE/Xclipse 940/Vulkan) · **iOS:** C11.2.2·C11.2.3 iPhone 17 Pro/iOS 26.2 Simulator 행렬 통과; C11.3.2 제한 표본 exact; C11.3.3 26 scene·65 node geometry 행렬과 Metal 2/2 exact(compositor 제출 전) · **미완료:** Spinon WPT 적합성·일반 numeric 및 leading/negative implicit grid line 생성, Spinon WPT 적합성, 전역 OOM 복구, 전체 CSS Grid 지원, 다른 Android 기기·driver 호환성, iOS 실기기·compositor 이후 픽셀 · **공개 API:** 아님 · **제품 CSS 지원:** 미선언

이 계약은 Stylo의 computed Grid CSS를 `spinon-layout` 입력으로 변환하고 Taffy Grid 계산 후보에 전달하는 Rust 내부 경계를 정의한다. `compute_runtime_block_flex_grid_style_layout` 경로는 HostDocument snapshot, 같은 mount-root의 Stylo view, typed cascade, style projection과 Taffy layout을 연결한다. Android/iOS 앱의 C11.1 고정 fixture도 이 공통 Rust 경로를 V8 runtime host·FFI와 연결한다. C11.1 Android 실기기와 iOS Simulator geometry는 각각 10 scene·40 node에서 통과했고, Android 고정 장면 표본은 7/7 exact였다. C11.2.1의 정확한 구현 후보 tree `fb9411cb7cc7f767699447d29a202a8fadca1ece`는 Android 16/API 36 SM-S731N과 iPhone 17 Pro/iOS 26.2 Simulator의 10 scene을 각각 실행했다. 양쪽 모두 성공 6/6·기대 거부 4/4, 21-node frame, geometry 최대 오차 0 CSS px, 성공 scene surface 표본 20/20 exact였다. Android 값은 실기기 PixelCopy, iOS 값은 compositor 제출 전 Metal drawable readback이다. Android API 37 AVD의 별도 표면 행렬은 ANGLE/SwiftShader 소프트웨어 경로이며 실기기 GPU 결과가 아니다. C11.2.1 구현은 현재 `origin/main`에 통합됐으며 공식 Spinon WPT runner·적합성, iOS 실기기와 compositor 이후 pixel parity는 미완료다. 이 계약은 CSS parser, 전체 CSS Grid 지원 또는 공개 `@spinon/*` API를 제공하지 않는다. 제품 상태는 [공식 상태 대장](../STATUS.md), 작업 분해는 [C11 계획](../../plan/c11-css-grid.md)을 따른다.

## 책임 경계

- `spinon-style`은 동일 문서·style·environment revision에서 computed CSS와 `RuntimeBlockFlexGridV1` profile diagnostic을 소유한다. 현재 단계는 explicit track list의 definite `px`, percentage, 양의 유한 `fr`, row auto-flow, row/column gap을 typed snapshot에 담는다.
- `spinon-style-to-layout`은 supported computed values만 engine-neutral `GridContainerInput`으로 변환하고 existing `LayoutInput`에 붙인다. HostDocument snapshot과 Stylo view의 document/root identity를 확인한다. 알 수 없는 track sizing, placement, definite basis 부재는 node/property/value가 식별되는 오류로 반환한다.
- `spinon-layout`은 Block·Flex·Grid 알고리즘 선택, track sizing candidate, item placement, frame 생성, allocation/index 오류와 layout revision을 소유한다. `origin/main` 기준선은 Taffy `0.14.0`을 사용했고 현재 후보는 vendored Taffy `0.15.0`을 `spinon-layout`의 모든 profile에 적용한다. trace 출력만 opt-in이며 의존성 버전 변경은 기존 profile 경로에도 영향을 주므로 C11.1~C11.3 회귀를 확인한다. 어느 버전도 호환성 판정 권위가 아니다.
- `spinon-style-to-render`/V8 runtime/FFI 및 Android/iOS app path에는 제한된 C11.1 고정 fixture 진입점이 추가됐다. Rust FFI는 `spinon_runtime_gpu_host_new_c11_1_grid_fixture`와 `spinon_runtime_gpu_host_eval_c11_1_grid_fixture`를 제공한다. Android는 `nativeCreateC11GridHost`/`nativeEvalC11GridFixture`, iOS는 `createRuntimeGpuHostWithC11_1GridFixture`/`evalRuntimeGpuC11_1GridFixture`로 호출한다. 이 fixture를 GPU scene에 전달하는 것은 확인했지만 일반 사용자 API나 전체 Grid 지원은 아니다.
- Android/iOS platform layer는 별도 native layout engine을 실행하지 않고 공통 Rust snapshot을 WGPU surface로 제출한다. 현재 검증은 위의 고정 fixture에 한정된다.
- C11.2.2는 별도 `RuntimeBlockFlexGridAutoPlacementV1` computed-style profile과 `GridPlacementMode::SparseRow`를 추가한다. 전용 FFI 진입점은 `spinon_runtime_gpu_host_new_c11_2_2_grid_auto_placement_fixture`와 `spinon_runtime_gpu_host_eval_c11_2_2_grid_auto_placement_fixture`다. 사용자용 공개 API가 아니다.

## C11.2.1 numeric explicit placement 구현 상태

C11.1의 all-auto row placement와 구분되는 `RuntimeBlockFlexGridPlacementV1` profile을 추가했다. Stylo computed longhand를 typed line/span 값으로 보존하고, `spinon-layout`에서 explicit track 경계와 line 변환을 검증한다. `RuntimeBlockFlexGridV1`의 기존 성공 의미는 유지한다. 상세 지원·거부 계약은 [C11.2.1 계획](../../plan/c11-2-1-explicit-grid-placement.md)을 따른다.

- Rust/Chrome style-to-layout fixture 9/9, runtime profile 3/3, layout-core placement 정규화 4개와 nested/hidden 경계 2개, FFI 인수 경계 1/1 및 full `bun run test`가 통과했다. 겹치는 item의 DOM paint snapshot 순서도 runtime test로 고정했다. 별도 profile을 쓰므로 C11.1의 auto-placement 동작을 C11.2.1 지원으로 확장해 세지 않는다. [구현 실패 관점 검토](./evidence/c11-2-1-grid-placement-implementation-review-2026-10-12.md).
- Android API 37 AVD와 iPhone 17 Pro/iOS 26.2 Simulator에서 고정 `numeric-lines` V8 fixture를 각각 실행했다. root 포함 4개 CSS px frame이 Chrome 154와 최대 차이 0이며 WGPU surface present marker가 나왔다. Android AVD는 ANGLE/SwiftShader 소프트웨어 backend다.
- [이전 Android AVD/iOS Simulator 10-scene runtime 행렬](./evidence/c11-2-1-mobile-runtime-matrix-2026-10-12/README.md)은 성공 6/6·기대 거부 4/4, 21-node frame, geometry 오차 0 CSS px를 기록했다. WPT runner·Spinon 적합성, iOS 실기기와 compositor 이후 parity는 미완료다. C11.2.1은 현재 `origin/main`에 통합됐지만 C11 상위 범위는 미완료다.

## C11.2.2 행 우선 sparse auto-placement 구현 상태

새 profile은 고정 explicit track 안의 definite/auto item 혼합 배치, sparse row cursor, 양의 implicit row와 단일 고정 px `grid-auto-rows`를 처리한다. `grid-auto-flow:row`만 허용한다. dense/column flow, implicit column, negative implicit row, intrinsic/auto implicit sizing, named line과 기타 계획 제외 입력은 구체 진단으로 거부한다. 보이는 직계 in-flow child만 배치하며 `order:0`을 요구한다. 중첩 Grid는 각 container에서 독립 계산한다. 세부 계약은 [C11.2.2 계획](../../plan/c11-2-2-sparse-row-placement.md)을 따른다.

- Chrome 154 고정 기준은 16 scene·69 node다. 고정 subset의 runtime scene 비교와 기대 거부 scene이 통과했다. 이는 Spinon WPT 적합성 결과가 아니다.
- Android 16/API 36 Samsung SM-S731N 실기기와 iPhone 17 Pro/iOS 26.2 Simulator에서 현재 source 기준 각각 16 scene, 성공 11/11·기대 거부 5/5, 69 node, geometry 최대 오차 0 CSS px를 확인했다. Android PixelCopy·iOS Metal drawable은 성공 11 scene·51 sample에서 최대 RGBA 채널 오차 0으로 Chrome DPR 1과 일치했다. iOS readback은 compositor 제출 전이다. [최신 Android 실기기 행렬](./evidence/c11-2-2-sparse-row-placement-android-runtime-matrix-2026-10-13/c1122-a-mv5u4e11-5cb5aa3d/README.md) · [최신 iOS Simulator 행렬](./evidence/c11-2-2-sparse-row-placement-ios-simulator-runtime-matrix-2026-10-13/c1122-i-mv5u5ax2-1ff58f57/README.md) · [이전 20개 실패 관점 검토](./evidence/c11-2-2-sparse-row-placement-implementation-review-2026-10-13.md).

[실행 결과와 로그](./evidence/c11-2-2-grid-allocation-failure-2026-10-13/README.md) · [실패 주입 20개 관점 계획 검토](./evidence/c11-2-2-grid-allocation-failure-plan-review-2026-10-13.md) · [구현 검토](./evidence/c11-2-2-grid-allocation-failure-implementation-review-2026-10-13.md).
- 이 결과는 `BTreeMap`·`BTreeSet` 등 infallible allocation, 전역 OOM 복구, Android/iOS 시스템 allocator에 직접 failure를 주입한 결과를 뜻하지 않는다. Spinon WPT 적합성·전체 CSS/Grid 지원도 공개 지원으로 승격하지 않는다.

## C11.2.3 dense·column auto-placement 제한 profile

`RuntimeBlockFlexGridAutoPlacementDenseV1`은 C11.2.2의 sparse row profile을 바꾸지 않고 `grid-auto-flow: row dense`, `column`, `column dense` 및 회귀용 `row`를 별도 내부 runtime 경로로 평가한다. 양의 implicit track 확장과 계획에서 고정한 auto-track sizing subset만 처리한다. typed computed `grid-auto-flow`, `grid-auto-rows`, `grid-auto-columns`를 cascade에서 받아 Rust placement 단계와 Taffy projection에 전달한다. 상세 허용값·거부값·계산 경계는 [C11.2.3 계획](../../plan/c11-2-3-dense-column-placement.md)에 고정한다.

- FFI entry point는 `spinon_runtime_gpu_host_new_c11_2_3_grid_auto_placement_fixture`와 `spinon_runtime_gpu_host_eval_c11_2_3_grid_auto_placement_fixture`다. scene source는 고정 25-scene runtime matrix에서 ID로만 선택한다.
- 위 C11.2.3 fixture 전용 FFI 심볼은 `spinon-ffi/c11-2-3-grid-fixture-test` Cargo feature로 gate한다. 이 feature는 `c04-runtime-gpu` 검증 앱 빌드에서만 켜며, 네이티브 C/C++ 호출부와 헤더는 `SPINON_ENABLE_C11_2_3_GRID_FIXTURE_TEST`를 함께 요구한다. 기본 앱 ABI에는 C11.2.3 scene 실행 진입점을 노출하지 않는다. C 함수명과 scene 선택 계약은 유지한다.
- 고정 Chromium 154 기준 25 scene·107 node 중 구현 성공 19, 기대 거부 6이다. Android SM-S731N 실기기와 iPhone 17 Pro/iOS 26.2 Simulator 각각에서 같은 행렬이 통과했고 geometry 최대 오차는 0 CSS px, 표면 sample은 각 99/99 exact였다. Android 실행은 actual PixelCopy 크기와 runtime CSS viewport의 비율을 사용한다. [최신 Android](./evidence/c11-2-3-dense-column-placement-android-physical-runtime-matrix-2026-10-13/c1123-a-mv5yld3e-4ded3cc6/README.md) · [최신 iOS Simulator](./evidence/c11-2-3-dense-column-placement-ios-simulator-runtime-matrix-2026-10-13/c1123-i-mv5ymb0x-10eed1fb/README.md) · [표면 구현 검토](./evidence/c11-2-3-mobile-surface-pixels-implementation-review-2026-10-13.md).
- 실제 Vec 예약 지점 여섯 곳(`VisibleItemList`, `RowLockedCursor`, `ExpandedRows`, `ExpandedColumns`, `OccupancyRows`, `OccupancyIntervals`)에서 allocator 실패를 주입했다. 정확한 `GridAllocationFailure`와 같은 worker의 후속 계산 복구를 확인했다. 이는 전역 OOM 복구나 다른 collection의 할당 실패를 보장하지 않는다. [실행 근거](./evidence/c11-2-3-grid-allocation-failure-2026-10-13.md).
- 이 profile은 public API나 제품 CSS 지원 선언이 아니다. 제한 profile의 geometry·표면 pixel gate는 지정 Android 실기기/iOS Simulator에서 통과했다. Spinon WPT 적합성, 전체 Grid/CSS 지원, iOS 실기기와 compositor 이후 픽셀은 완료하지 않았다.

## C11.3.1 정수 `repeat()` 사전 비교 상태

Chrome for Testing `154.0.8037.92`에서 고정 fixture 12 scene·29 node를 viewport `320×240 CSS px`, DPR 1·2로 캡처했다. 고정 WPT revision의 정수 repeat 후보 5개는 Chrome runner에서 5/5 PASS, unexpected 0이다. WPT runner JSON은 `headless: false`라고 기록하므로 실행 모드는 확정하지 않는다. 이는 Chrome oracle 결과이며 Spinon WPT 적합성 결과가 아니다.

C11.3.1에서는 새 `RuntimeBlockFlexGridTemplateV1` profile, 양의 정수 repeat 확장, N+1 line-name metadata/seam 병합, `grid-template`·`grid` track shorthand 경로와 아직 지원하지 않는 template areas 거부를 추가했다. explicit track은 최대 10,000개, 축별 expanded line metadata 예상 크기는 1 MiB까지 허용한다. 산술 overflow와 각 cascade/projection reserve failure는 오류로 종료하고 다음 계산의 복구를 확인한다. Android API 37 AVD와 iPhone 17 Pro/iOS 26.2 Simulator의 단일 `multi-track-repeat` runtime scene은 같은 item frame `30×20 @ (0,0)` 및 `24×22 @ (28,0)`을 냈다. 고정 Chrome 154 DPR 1 표면 기준 표본 5개는 Android AVD PixelCopy와 iOS Simulator Metal drawable에서 각각 RGBA exact로 일치했고, 변조한 sample 좌표는 두 플랫폼에서 표면 readback 전에 거부됐다. Android AVD는 ANGLE/Vulkan/SwiftShader 소프트웨어 backend이며 실기기 GPU 근거가 아니다. iOS 표본은 OS compositor 제출 전 drawable이다. Android 16 SM-S731N 실기기에서는 PixelCopy 5/5 RGBA exact를 기록했다. C11.3.1 단독 후보 source gate도 Android 실기기와 iOS Simulator에서 통과했다. compositor 이후 픽셀도 확인하지 않았다. ## C11.3.3 template areas·area placement 후보

`RuntimeBlockFlexGridTemplateV1`에서 Stylo typed `GridTemplateAreas`를 `ComputedCssGridTemplateAreas`로 복사한다. 소유 표현은 행·열 개수와 named area별 UTF-8 name 및 반열린 rectangle 네 경계만 저장한다. null cell과 반복 점은 별도 cell buffer를 만들지 않는다. 이름의 `-start`·`-end` alias를 explicit line-name metadata와 함께 resolve하며, explicit `foo-start`/`foo-end` pair로 만든 implicit named area도 양 축의 네 경계가 모두 explicit track 안에 있을 때 처리한다. bare area name은 area edge rule을, occurrence가 지정된 ident는 named line rule을 따른다. `grid-area`의 typed longhands가 숫자 line으로 정규화된 뒤 layout에 전달된다.

## C11.3.3 unknown-area trailing implicit named-line 후속 · 2026-10-21

전용 `compute_runtime_block_flex_grid_template_implicit_named_lines_style_layout` fixture 경로에서 explicit line-name이나 area/area alias에 없는 bare `<custom-ident>`를 양의 trailing implicit named line으로 해석한다. 반대쪽 definite line에서 named span을 검색할 때 explicit occurrence가 부족하면 필요한 만큼 trailing line을 생성한다. 기존 C11.3.1–3.2 projection wrapper는 그대로 missing name을 거부한다.

`GridPlacementMode::TemplateGridImplicitTracks`는 실제 named fallback으로 implicit line이 생성된 axis가 있을 때에만 사용한다. 이 mode는 row/column 양쪽의 `grid-auto-rows`와 `grid-auto-columns`가 고정 px일 것을 요구한다. 명시 numeric line/span이 implicit extent를 빌려가는 경로, leading/negative implicit line, `auto`/intrinsic implicit track sizing은 거부한다. 이름이 없는 sibling, 일반 C11.3 profile, 전체 Grid auto-placement로 이 mode를 확장하지 않는다.

고정 Chrome 154 oracle의 기존 26 scene·65 node matrix는 Android API 37 ARM64 AVD, Android 16/API 36 Samsung SM-S731N 실기기, iPhone 17 Pro/iOS 26.2 Simulator에서 각 26 scene·65 node, 성공 19·cascade fallback 5·기대 거부 2, visible frame 61개 geometry 오차 0 CSS px를 기록했다. 별도 overflow scene의 unknown-area item은 Chrome geometry `(175,125,15,5)`이며 AVD PixelCopy, SM-S731N PixelCopy, iOS Metal drawable 표본이 각각 3/3 exact다. 실기기 SurfaceFlinger renderer는 ANGLE/Xclipse 940/Vulkan 1.3.279로 기록했다. iOS readback은 OS compositor 제출 전이며 AVD는 ANGLE/Vulkan/SwiftShader다. Chrome의 viewport backdrop과 native host-owned surface 배경 차이는 sample에서 제외했다. 최신 source, 실행 ID, hash와 제한은 [후속 근거](./evidence/c11-3-3-unknown-area-implicit-lines-followup-2026-10-21/README.md)에 둔다. PR 상태와 검토 자료는 [PR #393](https://github.com/ohah/spinon/pull/393) 및 [실패 관점 30개](./evidence/c11-3-3-unknown-area-implicit-lines-followup-2026-10-21/pr-diff-review-30.md)에 연결한다.

이 후보는 C11.3.3 완료, WPT 적합성, 전체 CSS Grid 또는 공개 제품 CSS 지원을 선언하지 않는다. C11.3.3 상태와 공식 완료 집계는 미완료로 유지한다.

## 현재 제안 입력과 출력

`LayoutStyle.display`에 `Grid`가 추가될 때도 기존 값을 재해석하지 않는다. 새 Grid container input은 definite content-axis basis, ordered row/column track lists, row/column gap, auto-flow mode를 전달한다. 각 grid item은 source NodeId, optional explicit line/span placement, used margin/size/alignment 값을 받는다. 첫 구현은 다음 subset만 허용한다.

- `display:grid` block-level container
- definite axis에서 fixed length, resolved percentage, positive `fr` 명시 track
- 기본 `grid-auto-flow:row` auto placement와 row/column gap
- fixed-size, non-text in-flow grid items, `order:0`
- Block·Flex·Grid 간 중첩은 각 child algorithm과 동일 revision을 보존할 때만 허용

출력은 입력 `LayoutInputRevision`을 그대로 echo하는 NodeId별 CSS px border-box frame이다. 값의 비정상, owner/child 불일치, unsupported CSS, revision mismatch, overflow 또는 allocation failure가 있으면 전체 계산을 실패 처리한다. 이전 scene·0 크기·기본 Block layout으로 대체하지 않는다.

## Taffy 경계와 현재 layout-core

- `spinon-layout`의 main C11.1–3 경로는 `grid` feature와 custom-tree `LayoutGridContainer`를 연결한다. C11.4 후보 worktree는 추가로 vendored Taffy `0.15.0`을 사용해 단계 추적 API를 제공한다. 엔진 중립 입력은 `GridContainerInput`·`GridItemInput`이며 C11.3.2부터 explicit line-name metadata와 named placement를 Stylo→layout projection에서 해석한다. layout-core와 HostDocument→Stylo→Taffy unit path는 source-order, gap, definite percentage, unsupported flow/placement, stale/revision identity, root mismatch를 검사한다. pinned Chromium 직접 geometry 비교는 fixed-track scene 1개·5 node와 C11.3.2 후보의 named-line scene들을 별도 fixture로 다룬다. Taffy `Style`은 Grid named-line·area 버퍼까지 각 노드에 포함해 8 MiB worker의 1,024-depth debug 실행을 실패시켰다. 계산 트리에는 현재 profile이 소비하는 필드만 가진 `CompactTaffyStyle`을 저장하며, style 크기 회귀와 동일한 worker depth 시험을 통과했다. - `origin/main`의 Taffy `0.14.0`과 현재 후보의 vendored Taffy `0.15.0`은 `MAX_GRID_TRACKS`를 축마다 10,000으로 두고 explicit grid를 이 값에서 clamp한다. 후보는 모든 `spinon-layout` profile을 0.15.0으로 전환하므로 기존 profile 회귀도 확인해야 한다. ## C11.4 raw intrinsic source input, contribution input과 measure callback trace

아래 Rust 계약은 C11.4 단계 A의 입력 계측 조각이다. CSS Grid contribution을 계산하거나 public CSS 지원을 선언하지 않는다.

- `LayoutOutput.intrinsic_measurements`는 시각 layout tree의 Taffy `SizingMode::InherentSize` leaf measure callback에서 관찰한 `LayoutIntrinsicMeasurement` 목록이다. in-flow Grid container의 직접 child에 해당하는 text/replaced 측정만 기록한다. flow-only 보조 계산은 기록하지 않으며, out-of-flow child는 Grid item으로 분류하지 않는다.
- callback trace 항목은 입력 `NodeId`, 최종 `LayoutInputRevision`, 측정 원천, Grid item의 `LayoutStyle`, width/height 축별 `MinContent`·`MaxContent`·`Definite(px)`, callback의 known dimensions와 parent content-box size, callback이 반환한 content-box size를 보존한다. Replaced 원천은 natural size를, text 원천은 `FontRegistryRevision`을 추가로 보존한다.
- Taffy inherent-size callback의 `available_space`가 항상 min/max-content인 것은 아니다. definite 값도 유효한 관찰 결과이며 이 목록만으로 CSS contribution 종류를 추론하면 안 된다. callback 호출 또는 cache hit에 결과 수집을 의존하지 않도록 별도의 `LayoutOutput.grid_item_intrinsic_inputs` 원본 목록을 제공한다.
- 원본 목록은 원래 입력 트리의 직접 Grid child 순서와 container ID를 함께 보존한다. 숨겨진 subtree, absolute/fixed child, 원래 자식이 있는 non-leaf는 제외한다. Text source는 Parley `TextIntrinsicInlineSizes`의 min/max-content inline/block 값과 같은 font registry identity/revision을 보존한다. Replaced source는 C14.3 intrinsic natural content-box size를 보존한다. 모든 항목은 최종 `LayoutInputRevision`과 `LayoutStyle`을 함께 갖는다.
- `LayoutGridItemIntrinsicInput::contribution_input()`은 raw source에서 width/height 축별 min/max-content 후보, preferred/min/max typed size, margin·padding·border, 전체 `item_style`, source 및 revision을 값으로 묶는다. 전체 style은 `box-sizing`, aspect ratio, overflow, order 등 이후 단계 입력도 보존한다. Text 후보는 Parley의 두 intrinsic 축 결과이고, replaced 후보는 natural width/height를 각각 min/max 후보로 둔다. 이 메서드는 output에 별도 vector를 만들거나 layout-time allocation을 추가하지 않는다. 반환값의 `outer_size()`는 고정 길이 edge와 자동 여백만 합산하며, 백분율·`calc()` edge는 basis가 아직 연결되지 않아 `UnsupportedIntrinsicSizing`으로 거부한다. 이 입력을 기록한다고 현재 Grid validator가 거부하는 기존 0 최소값 예외 외의 min/max constraint까지 지원하는 것은 아니다.
- 두 목록은 목적이 다르며 서로 대체하지 않는다. 원본 목록은 callback이 관찰한 특정 available-space 응답을 모방하지 않는다. contribution input은 fixed edge를 outer-size 후보에 합산할 수 있지만 CSS Grid의 preferred/min/max contribution을 선택하지 않고, aspect-ratio 축 전달·백분율 edge basis·item span·automatic minimum·track sizing도 계산하지 않는다. 직접 anonymous Grid text run은 C11.4 opt-in fixture subset에서 원본 source node·anchor·owner·순서 provenance를 보존하도록 연결했다. 일반 Grid runtime 경로, nested/non-leaf item의 aggregate measurement/provenance, descendant text의 item-level provenance는 여전히 미지원이다.
- 두 output 목록의 벡터 예약은 `try_reserve(1)`로 실패를 전달한다. 기록 오류는 layout 계산 종료 뒤 `LayoutError`가 되어 부분 `LayoutOutput`을 게시하지 않는다. 해당 원본이 없는 출력에는 빈 벡터를 반환한다.
- `LayoutIntrinsicMeasurement`, `LayoutGridItemIntrinsicInput`과 `LayoutOutput.grid_track_sizing_traces` 자료는 Rust `spinon-layout` 출력에만 있다. 이 값들을 FFI 또는 공개 `@spinon/*` API로 노출하지 않는다. 별도 opt-in runtime fixture FFI는 고정 C11.4 scene의 상태·frame과 제한된 trace report를 검증용 앱 로그로 전달하며, 제품 API가 아니다.

## C11.4 direct image Grid transferred-size suggestion 후보

2026-10-19 현재 구현 후보는 `RuntimeBlockFlexGridTrackSizingV1`의 direct HTML `img` Grid item에 한해 replaced item의 natural 또는 authored aspect ratio와 반대 축 definite preferred size에서 transferred-size suggestion을 계산한다. 반대 축 preferred size에 authored min/max를 먼저 적용하고 ratio로 변환한 뒤, content-box인 경우 target 축 padding/border를 더하고 target 축 preferred/max size로 제한한다. border-box 크기는 장식을 다시 더하지 않는다. 이 단계는 [CSS Grid Level 1 §6.6](https://www.w3.org/TR/2025/CRD-css-grid-1-20250326/#min-size-auto)의 specified-size → transferred-size → content-size 순서와 automatic minimum 분기에 연결되며, 제한 profile 밖의 authored ratio min/max 입력·non-image·nested image는 거부한다.

고정 Chrome 155 관찰은 27개(직접 replaced image 26, non-replaced control 1)다. pure Rust matrix는 직접 image 23개, scrollable-overflow control, content-/border-box decoration 두 건과 non-replaced control을 비교한다. Android API 37 ARM64 AVD와 iPhone 17 Pro/iOS 26.2 Simulator 앱은 7개 장면 모두의 frame·trace·screenshot을 통과했고 grid 바깥 PixelCopy/Metal 색 표본은 overflow 장면에서만 읽었다. 원본과 정확한 적용 범위는 [Chrome oracle·구현 실패 관점 검토](./evidence/c11-4-image-ratio-transfer-2026-10-19/README.md) · [구현 검토 20개](./evidence/c11-4-image-ratio-transfer-2026-10-19/implementation-review-20.md) · [Simulator 실행 근거](./evidence/c11-4-image-ratio-transfer-simulator-2026-10-19/README.md)에 둔다. dynamic replacement/cache invalidation, 다른 Grid contribution 조합, anonymous/nested/multiple item, WPT 및 전체 표준 단계 비교는 미검증이다. 제한 fixture 후보이며 공개 이미지/Grid 지원이나 C11.4 완료를 뜻하지 않는다.

## C11.4 cross-axis fixed max track clamp 후속 후보

2026-10-19 후속 구현은 direct HTML `img` item의 transferred-size suggestion 입력이 반대 축에서 item이 span한 모든 track의 max sizing function이 fixed인 경우 그 합계로 제한되도록 한다. Taffy의 GridTrack slice는 gutter를 sizing function이 있는 항목으로 포함한다. content-box item은 반대 축 track border-box 한도에서 padding/border를 빼고 0 아래를 막은 뒤 ratio 변환을 한다. 새 양방향 fixture는 현재 단일 8px fixed track만 사용한다. 여러 fixed track과 gutter의 합산 동작은 코드 경계에 있으나 직접 oracle로 검증하지 않았다.

## C11.4 negative implicit track sizing

`RuntimeBlockFlexGridTrackSizingV1`의 numeric negative line은 explicit track 수를 기준으로 signed boundary coordinate로 해석한다. TrackSizing normalizer는 signed occupancy와 row/column auto-placement cursor를 유지하고, 최종 checked extent 뒤에 origin shift를 적용해 Taffy line으로 변환한다. explicit `none`의 단일 경계선, reversed/equal line, span, hidden child 제외, 양·음 방향 `grid-auto-*` 목록 순환을 제한 구현한다. 양수 line이 만드는 positive implicit track의 기존 순환은 유지한다.

## C11.4 auto-repeat과 typed implicit track sizing 후속

2026-10-20 후속은 위 auto-repeat placement profile에서 `grid-auto-rows`와 `grid-auto-columns`의 비어 있지 않은 `GridTrackSize` 목록을 기존 Taffy track converter로 변환한다. 유효한 `LengthPx`, percentage, fraction, `auto`, `min-content`, `max-content`, `minmax()`, `fit-content()`와 기존 CSS math의 `calc()`를 각 축의 authored order대로 처리한다. explicit grid 뒤는 정방향, 앞쪽 implicit tracks는 역방향 cycle이다. repeat count·signed line 해석과 `auto-fit` empty-track 및 인접 gutter collapse는 기존 경계를 유지한다.
