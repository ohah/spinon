- **계약 버전:** `0.1.0-draft` · 출시 전 숫자 버전 고정
- **상태:** 제한 Root HTML Block paint slice 구현·Simulator 검증 완료 · C04.12 전체 미완료
- **상위 계획:** [앱 루트 HTML과 문서 환경 metadata](https://macstudio.tailed42f2.ts.net/spinon/plan/c04-root-html-document-environment.html)

## 목적과 현재 범위

기존 `RuntimeSession::new()`의 빈 `HostDocument` 동작을 유지하면서, 호스트가 전달한 UTF-8 HTML document를 pinned `html5ever` tree construction으로 파싱해 V8 `document`와 HostDocument cascade 입력으로 사용한다. HTML source 안의 `<script>`는 실행하지 않는다. Android/iOS 기본 앱은 bundle의 `index.html`을 새 root-HTML session에 전달하고 별도 `root-app.js`를 같은 session에서 평가한다.

현재 구현은 `<meta name="viewport">`에서 CSS layout viewport와 초기 visual viewport, 별도 `page_scale`을 계산하고 OS의 light/dark 선호를 CSS `prefers-color-scheme` 입력에 전달한다. 루트 HTML 전용 author cascade profile은 layout viewport의 width/height 및 기존 pointer·scheme media query allowlist를 사용한다. `<meta name="color-scheme">`의 초기 document scheme과 native 선호도는 별도 typed 값으로 반환한다. 후속 Canvas slice는 completed CSS cascade의 실제 HTML root computed `color-scheme`을 metadata 및 OS preference와 결합해 Android/iOS native content root의 제한된 Canvas background로 사용한다. Chromium `155.0.8059.85` 기준 light `#ffffff`, dark `#121212`를 scheme fallback으로 적용하며 universal system palette를 뜻하지 않는다. 별도 후속 slice는 `page_scale`과 DPR을 선택된 renderer scene snapshot에 명시적으로 붙여 WGPU 표면 좌표로 변환한다. 추가 Root HTML Block paint slice는 opt-in fixture profile에서 같은 parsed HTML tree의 제한 block geometry와 background paint를 실제 WGPU surface에 연결한다. 이 mapping과 fixture는 기본 `RuntimeSession`의 모든 HTML layout·paint에 자동 연결되지 않는다. 일반 HTML layout·paint, 실제 DOM text rendering, form controls는 지원하지 않으므로 C04.12는 미완료다.

## 입력과 parser 제한

- Rust 진입점은 `RuntimeSession::new_with_root_html(&str)`이며 HTML5 document mode를 사용한다. C ABI 진입점은 `spinon_runtime_session_new_with_root_html(const char *, size_t, char *, size_t)`다. 기존 생성 함수와 JavaScript-only 동작은 바뀌지 않는다.
- 기본 앱 asset contract는 UTF-8 `index.html`과 별도 `root-app.js`다. Android assets와 iOS app bundle에 둘 다 포함하고, root HTML을 먼저 session document로 파싱한 뒤 JS source를 같은 session에서 평가한다. HTML의 `<script>`를 자동 실행하지 않는다. 기존 `app.js` native smoke는 별도 JavaScript-only 실행으로 남긴다.
- HTML parser는 pinned `html5ever = 0.40.1`이다. DOM adapter는 제품용 `TreeSink`를 구현한다. test-only·비제품 DOM 구현을 선언한 `markup5ever_rcdom`을 사용하지 않는다.
- source는 유효한 UTF-8이어야 하고 최대 크기는 1,048,576 bytes다. HTML5 tokenizer/tree builder의 정상 복구 경로를 적용하며 원본 parse error 횟수는 최대 128까지 계수한다.
- import 가능한 tree는 최대 65,536 node, 최대 depth 256, 전체 16,384 attribute다. source 자체도 1,048,576 bytes로 제한한다. `NoQuirks` document만 받으며, quirks/limited-quirks document는 세션 생성 오류로 거부한다.
- `HostDocument`가 표현하지 못하는 doctype·comment·processing instruction은 보존하지 않는다. element와 text 순서는 보존한다. namespace가 있는 attribute는 현재 batch ABI가 namespace를 표현하지 못하므로 전체 생성 오류로 거부한다. element namespace는 보존한다.
- `<template>`의 별도 contents fragment는 일반 child tree로 연결하지 않는다. `<script>`는 inert element/text로만 문서에 남고 실행하지 않는다. 외부 stylesheet fetch·script 실행·dynamic document mutation과 DOM parser API는 범위 밖이다.
- parse/import 실패는 V8 isolate를 공개하기 전에 session startup 실패로 반환한다. 부분 HostDocument는 해당 worker 초기화와 함께 버린다.

## 환경 API와 cascade 범위

- Rust API는 `RuntimeSession::set_root_html_environment(surface_width_px, surface_height_px, device_scale_factor, media_environment)`이다. 앞의 두 값은 surface physical pixel, device scale은 physical pixel per CSS pixel이다. JavaScript-only session에는 root HTML metadata가 없으므로 `InvalidEnvironment`로 실패한다.
- 내부 C ABI `spinon_runtime_session_set_root_html_environment`도 같은 입력을 받는다. `prefers_color_scheme` 입력은 `0=light`, `1=dark`이고, output struct `SpinonRuntimeRootHtmlEnvironment`에는 CSS layout viewport, 초기 visual viewport, device scale, 별도 page scale, prefers/document scheme(`0=light`, `1=dark`)과 environment revision이 들어간다. 성공은 `0`, 인자·세션 유형·환경 오류는 `-1`, 종료 중은 `-6`, CSS worker 불능은 `-7`이다. 호출자는 세션 해제와 병행하지 않는다. 이는 앱 native bridge용 내부 ABI이며 공개 제품 API가 아니다.
- Canvas native bridge는 `spinon_runtime_session_resolve_root_html_canvas`와 `SpinonRuntimeRootHtmlCanvas`를 사용한다. 이 호출은 environment를 설정한 뒤 `0–60,000 ms` 동안 cascade completion을 기다리고, Canvas RGBA, used scheme, generation/document/render-tree/style/environment revision key를 반환한다. timeout `-10`, stale key `-12`, duplicate scheme metadata `-13`, unsupported computed scheme `-14`, root/style 누락 `-11`, 선택되는 computed background가 지원 profile 밖이면 `-15`다. 오류 시 output struct는 쓰지 않는다. cascade 결과는 UI thread에서 기다리지 않는다. Android/iOS adapter는 background executor에서 호출하고 결과 key가 유효할 때만 main/UI thread의 native content background를 바꾼다.
- Root HTML CSS cascade는 `width`, `height`, `min-width`, `max-width`, `min-height`, `max-height`의 px 길이 또는 0 media query와 `prefers-color-scheme`, `pointer`/`any-pointer`, `hover`/`any-hover`의 기존 제한 surface를 받는다. 허용한 query list와 `and`·`not`·`only`·`screen`·`all` 조합만 통과하며 다른 feature, 단위, 속성, malformed condition은 전체 cascade 오류로 거부한다. 이 허용 범위는 `new_with_root_html` profile에만 추가됐고 JavaScript-only/default profile은 viewport dimension query를 계속 거부한다.
- `color-scheme` author property는 Root HTML computed-style output에만 추가된다. layout adapter는 이 값으로 OS scheme을 바꾸거나 Canvas/system color를 그리지 않는다. `meta` 초기 document scheme도 `prefers-color-scheme` 입력과 합치지 않는다.
- layout width는 `max(requested_width, screen_css_width / page_scale)`이다. layout height는 이 resolved layout width에 surface의 physical height/width 비율을 곱한다. visual width/height는 screen CSS width/height를 page scale로 나눠 계산한다. 예를 들어 `width=500, initial-scale=1`에서는 layout `500×1082.0513`, visual `390×844` CSS px이며, DPR 3은 별도 값으로 남는다. CSS media query는 layout viewport를 읽는다.
- Environment revision은 CSS layout viewport, DPR 또는 media input이 바뀔 때 증가하고 같은 입력을 다시 전달하면 유지된다. cascade snapshot은 비동기 latest-wins worker에서 갱신된다. `page_scale`과 visual viewport 값은 snapshot에 남는다. 아래 opt-in scene mapping 외에는 이를 surface transform·pinch zoom·`visualViewport` JavaScript API에 연결하지 않는다.

### Root Canvas background slice

- metadata가 없거나 단일 metadata 값이 invalid이면 지원 scheme이 없는 것으로 처리한다. CSS root computed value가 `normal`이면 metadata 지원 목록을 선택하고, metadata도 없으면 light Canvas를 사용한다. 명시적 root CSS scheme은 metadata보다 우선한다. `prefers-color-scheme`은 언제나 OS preference를 유지한다.
- `<head>`의 `meta name="color-scheme"`이 두 개 이상이면 이 Canvas slice는 새 색을 게시하지 않고 기존 background를 유지한다. HTML Standard에서 이 metadata는 유일해야 한다. malformed duplicate 동작을 Chrome별 복구 결과에 맞춰 구현하지 않는다.
- canvas 단색은 computed HTML namespace `html`의 불투명 `background-color`를 우선하고, root가 투명이면 직접 연결된 HTML `body`의 배경색을 사용한다. 둘 다 투명하거나 body가 없으면 root computed `color-scheme`과 metadata·OS preference에서 얻은 Canvas fallback을 사용한다. 불투명 root가 선택되면 body 배경은 Canvas 색 선택에 영향을 주지 않으며, body box 자체의 paint는 구현하지 않는다.
- 선택되는 author `background-color` 후보는 Stylo computed source color space가 sRGB이며 alpha가 0 또는 1이고, 모든 opaque channel이 RGBA8 바이트 경계와 정확히 일치하는 경우만 지원한다. 선택되지 않는 body의 표현 가능한 색은 opaque root Canvas 결과에 영향을 주지 않는다. 다만 root HTML cascade profile 검증은 document snapshot 전체에 적용되므로, 선택되지 않는 node의 profile 밖 계산 색이나 선언도 cascade 전체를 실패시킬 수 있다. `var()`와 media query는 기존 root HTML profile에서 computed 결과가 이 경계를 만족하면 통과한다. system color와 system color를 담는 custom property, HSL/HWB, wide gamut·linear color, fractional sRGB, 선택되는 후보의 부분 alpha, CSS image/gradient, stale revision은 새 색으로 처리하지 않는다. Stylo가 system color의 원래 키워드를 computed absolute color에서 제거하므로 parsed declaration 단계에서 fail-closed한다.
- Canvas palette fallback은 pinned Chromium `155.0.8059.85`에서 관찰한 sRGB `#ffffff` / `#121212` 두 값에만 한정한다. forced colors, `CanvasText`, form control theme은 포함하지 않는다.
- 새 [Chrome 사전 비교와 simulator 실행 근거](./evidence/c04-12-root-canvas-color-scheme-2026-10-17/README.md)는 API 37 ARM64 AVD와 iPhone 17 Pro/iOS 26.2 Simulator의 light→dark→light 실행에서 environment/cascade revision 0→1→2 및 content 중앙 RGB를 확인한다. 캡처는 native root background만 보여 주며 HTML body/text/layout·paint 결과가 아니다.
- 이 후속 범위의 [Chrome 사전 비교와 Android/iOS Simulator 실행](./evidence/c04-12-document-canvas-background-2026-10-18/README.md), [구현 계획](../../plan/c04-12-document-canvas-background.md), [구현 실패 검토](./evidence/c04-12-document-canvas-background-2026-10-18/implementation-review-20-2026-10-18.md), [PR 최종 diff 적대 검토](./evidence/c04-12-document-canvas-background-2026-10-18/pr-delta-review-30-2026-10-18.md)는 root/body cascade 색과 native content root 결과를 구분한다. 이 slice도 C04.12 전체 완료를 의미하지 않는다.

## DOM 관찰 계약

- V8 `document.documentElement`는 문서의 첫 element child를 반환하고, 없으면 `null`을 반환한다. `document.head`와 `document.body`는 첫 root가 HTML `html` element인 경우 그 직접 자식 중 각각 `head`·`body`인 첫 element를 반환하고, 없으면 `null`이다.
- HTML parser가 생성한 `<html>`, `<head>`, `<body>`와 나머지 element/text는 같은 문서 generation과 순서를 갖는 HostDocument 입력이다. HTML `meta`, title 및 기타 비표시 노드는 UA/CSS 처리 대상이며 임의로 visible layout root로 바꾸지 않는다.
- 기본 app `root-app.js`는 루트 `lang`, head/body 부모 관계, viewport와 color-scheme metadata node/content, root style text, body content를 실제 V8에서 읽는다. 이후 `data-runtime` attribute를 설정하고 같은 session에서 다시 읽는다. 이 assertion은 parser가 metadata element를 DOM으로 보존하는지만 확인하며 viewport·OS scheme·computed CSS·Canvas·화면에 적용되는 효과를 확인하지 않는다.
- C04.11에 포함된 연결 `<style>` 수집은 같은 HostDocument tree를 사용한다. `documentElement`의 CSS `:root` 의미, UA root blockification과 body/root layout은 별도 검증 전까지 보장하지 않는다.

## 초기 viewport·color-scheme metadata 환경

- Metadata는 parser가 만든 동일 HTML document의 HTML namespace `<head>` 안 `<meta>` 요소에서 수집한다. 태그와 속성 이름 및 지원 키워드는 ASCII 대소문자를 구분하지 않는다. `content` 값의 원문 attribute는 DOM에 계속 보존한다.
- 호스트 입력은 surface pixel width/height, 양수 유한 `deviceScaleFactor`, OS의 light/dark 선호와 pointer capability다. surface pixel 크기를 device scale로 나눈 값을 metadata 적용 전의 모바일 screen CSS 크기로 사용한다. CSS layout viewport, 초기 visual viewport, device scale과 page scale은 별도 값이다.
- 이 slice의 viewport descriptor allowlist는 `width=device-width`, 양수 CSS px `width`, 양수 `initial-scale`이다. `content`는 comma/semicolon 구분을 허용하며, 같은 element 안에 descriptor가 반복되면 마지막 유효 값이 앞선 값을 대체한다. 여러 viewport `<meta>`가 있으면 마지막 요소를 사용한다. 이 duplicate element 규칙은 [고정 Chrome 155 사전 비교 fixture](./evidence/c04-root-html-document-environment-2026-10-17/mobile-duplicate-width.html)의 관찰에 한정한다. 지원하지 않는 descriptor는 무시하고, 유효하지 않은 width/scale 값은 그 descriptor만 생략해 기본 계산을 유지한다.
- viewport metadata가 없으면 모바일 기본 layout width는 `980 CSS px`이고 page scale은 `min(screenWidth / 980, 1)`이다. `width=device-width`는 screen CSS width를 요청한다. 고정 width는 initial scale 적용 후 screen CSS 폭보다 좁은 layout viewport를 만들지 않도록 확장한다. layout height는 resolved layout width에 surface aspect ratio를 곱한다. 초기 visual width/height는 screen CSS width/height를 page scale로 나눈다. 고정 Chrome 155 비교는 [기존 환경 행렬](./evidence/c04-root-html-document-environment-2026-10-17/README.md)과 [visual viewport 확장 행렬](./evidence/c04-12-visual-viewport-2026-10-17/README.md)에 나눠 기록한다. metadata가 desktop surface에 미치는 동작과 pinch zoom은 이 slice에서 정의하지 않는다.
- `meta name="color-scheme"`은 `<head>`에서 첫 요소만 선택한다. `content`에서 지원하는 목록은 `light`, `dark`, 둘의 조합, `only light`, `only dark`다. 목록에 OS 선호가 있으면 그 scheme을 initial document scheme으로 선택하고, `only`는 지정된 scheme을 선택한다. 값이 비어 있거나 지원되지 않으면 initial document scheme은 light다. 이는 UA 초기 scheme 선택 결과이지 OS 선호가 아니다. 두 개 이상의 해당 meta 요소가 있으면 Canvas 색 적용은 fail-closed한다.
- `CssMediaEnvironment.color_scheme`과 `prefers-color-scheme`는 native OS/user preference만 반영한다. 문서 metadata가 `dark`여도 OS가 light면 `(prefers-color-scheme: light)`가 참이고, `document_color_scheme`은 별도 initial scheme 결과다. Canvas 선택에는 실제 HTML root의 cascade 완료 computed `color-scheme`을 사용한다. 값이 `normal`이면 metadata supported list와 OS 선호를 결합하고, metadata가 없거나 invalid이면 pinned Chromium 155의 light Canvas fallback을 사용한다. 명시 root CSS scheme은 metadata보다 우선한다.
- Root HTML session은 viewport metadata를 적용한 CSS viewport와 호스트 `deviceScaleFactor`·media environment로 cascade를 재요청한다. `pageScale`은 environment snapshot에 별도로 남고, 일반 scene publish에는 자동 적용되지 않는다. Android UI mode 변화와 iOS trait 변화는 native preference를 다시 전달한다. Simulator 확인은 환경 입력·revision, cascade result, native content root Canvas 배경을 관찰한다. HTML body·layout·text·paint는 통과 기준이 아니다.
- 이 단계의 실행 근거는 metadata typed snapshot, `@media` viewport width/height·`prefers-color-scheme` computed result, root CSS `color-scheme` value, environment/cascade key 및 Canvas fill을 구분한다. Canvas 색은 pinned Chromium 155 sRGB `#ffffff`/`#121212` 두 값뿐이다. Android/iOS Simulator 화면은 native content root background 표본이며 page zoom, HTML rendering, compositor·screenshot equivalence를 주장하지 않는다.

2026-10-17 viewport correction의 [계획과 Chrome·Android/iOS Simulator 근거](./evidence/c04-12-visual-viewport-2026-10-17/README.md)는 layout/visual 크기를 별도로 반환하고 고정 폭 metadata에서 layout 높이가 CSS media query에 쓰이는지 확인한다. 그 Simulator 캡처는 opt-in 앱 fixture의 PASS 보고 화면이며 HTML body의 layout·paint 또는 renderer transform을 증명하지 않는다. scene transform은 아래 별도 근거를 따른다. [구현 실패 관점 검토](./evidence/c04-12-visual-viewport-2026-10-17/implementation-review-20.md)도 함께 기록한다.

### 초기 page-scale renderer scene slice

- `RuntimePageScaleTransform::new(device_scale_factor, page_scale)`은 두 양수 유한 값을 분리해 보존하고 `DPR × page_scale`이 유한한 양수일 때만 생성된다. `RuntimeRenderSnapshot::with_page_scale_transform`은 이 mapping을 opt-in으로 연결한다. 잘못된 입력은 `InvalidPageScaleTransform`으로 거부한다. 기존 생성자는 mapping을 설정하지 않으므로 기존 surface-fit 좌표를 유지한다.
- mapping이 있는 scene의 WGPU colored box, border, image, pre-rasterized glyph 좌표를 CSS 원점 `(0,0)` 기준 `DPR × page_scale`로 surface에 투영한다. clip은 CSS scene 좌표에서 유지하고 최종 결과를 physical surface 경계에서 자른다. layout viewport, CSS hit-test, image UV·source raster, paint order는 scale에 맞게 재정의하지 않는다. glyph coverage mask는 기존 DPR raster를 확대·축소하며 page scale별 text rerasterization을 하지 않는다.
- 실제 HTML body renderer가 아니라 C04.12 opt-in root-HTML app fixture에서 C ABI가 반환한 environment 값으로 고정 scene을 만든다. Chrome `155.0.8059.85`, iPhone 12 emulation, `1170×2532` target의 `initial-scale=0.5`, `initial-scale=2`, `width=500, initial-scale=1` 세 case에서 각각 surface pixel 10개를 대조한다. 각 case는 box 내부·반열린 경계·visual viewport의 오른쪽/아래쪽 잘림과 바깥 control, image, glyph를 포함한다.
- 앱 fixture는 Android API 37 AVD와 iPhone 17 Pro / iOS 26.2 Simulator의 embedded WGPU readback 3 case / 30 sample 결과를 확인한다. 앱 화면 캡처는 fixture PASS 보고 화면이다. 실제 body paint나 전체 HTML renderer가 아니다. CSS hit-test 입력 좌표 변환, pinch/pan, scroll 뒤 visual viewport, safe area, 일반 DOM layout·paint, dynamic/pinch scale, text rerasterization은 미지원이다. 구현 계획 및 Chrome oracle는 [page-scale 계획](../../plan/c04-12-page-scale-rendering.md), 앱·WGPU 실행과 화면은 [page-scale 실행 근거](./evidence/c04-12-page-scale-rendering-2026-10-17/README.md)에 기록한다.

### Parsed root HTML Block paint scene slice

- 전용 `c04-12-root-html-block-paint-fixture-test` opt-in feature만 `RuntimeCalculationProfile::RootHtmlBlockPaint`와 native fixture ABI를 활성화한다. 동일 HTML5 parser의 HostDocument snapshot, CSS viewport, `prefers-color-scheme` environment revision을 Stylo cascade → Taffy layout → `RuntimeRenderSnapshot` → WGPU renderer까지 전달한다. 별도 parser나 synthetic JS DOM은 만들지 않는다.
- visible success subset은 HTML namespace의 `html`, `body`, `main`, `div` Block node와 `display:block|none`, 고정 px sizing, zero margin, transparent 또는 완전 불투명 8-bit sRGB `background-color`다. fixture는 `head`와 `display:none` subtree를 box와 paint에서 제외하고 `html` root `320×240`, `body` `320×200`, hero `160×32`, child `120×24`를 비교한다. visible text, controls, intrinsic sizing, partial alpha, wide-gamut 색, 일반 author CSS, 일반 Bootstrap 화면 및 전체 HTML conformance를 지원하지 않는다.
- layout에서 생략하는 text node는 CSS `white-space: normal`의 HTML ASCII 접이 공백(space, tab, LF, CR, form-feed)만 허용한다. NBSP와 다른 Unicode whitespace는 visible text로 남아 이 slice에서 거부된다.
- [Chrome 155 사전 비교](./evidence/c04-12-root-html-block-paint-precomparison-2026-10-18/README.md)와 Android API 37 ARM64 AVD 및 iPhone 17 Pro / iOS 26.2 Simulator의 [구현·표면 캡처 근거](./evidence/c04-12-root-html-block-paint-2026-10-18/README.md)는 light/dark style, geometry, node order, 5개 RGBA 표본을 연결한다. AVD WGPU surface가 `COPY_SRC`를 지원하지 않아 Android는 `SurfaceView` PixelCopy로 실제 표면 결과를 읽고 Rust의 projected pixel coordinates와 대조한다. iOS는 Metal drawable을 직접 읽으므로 compositor 전 표본이다. 두 경로는 같은 readback 경계로 합쳐 해석하지 않는다.
- Android API 37 emulator는 ANGLE/SwiftShader software backend다. iOS 결과도 Simulator 전용이다. 어느 쪽도 실기기, hardware GPU, compositor 이후 최종 표시 픽셀을 증명하지 않는다. 이 opt-in fixture는 기본 app의 모든 parsed HTML을 그리지 않으며 C04.12 상위 항목을 완료하지 않는다.
- 별도 [구현 실패 관점 20개 검토](./evidence/c04-12-root-html-block-paint-implementation-review-20-2026-10-18.md)는 partial alpha와 Display-P3가 일반 sRGB converter에서 통과할 수 있는 경계를 찾아 profile 전용 색 검증으로 수정했다. 수정 뒤 `spinon-style` 전체 180개와 opt-in `spinon-runtime` 집중 2개 테스트가 통과했다. [실행 근거](./evidence/c04-12-root-html-block-paint-2026-10-18/README.md)는 Simulator 캡처가 색 경계 수정 전임을 구분한다.

## 오류·검증 경계

- 잘못된 UTF-8, source/node/depth budget 초과, quirks mode, unsupported namespaced attribute, HostDocument quota 및 parser/tree 변환 오류는 세션 생성 실패다. source 일부만 화면에 게시하지 않는다.
- 이 제한 계약은 앱이 받은 임의 HTML 전체의 WHATWG conformance, 위 allowlist 밖 metadata 의미, page zoom, 일반 CSS layout·paint 동등성을 뜻하지 않는다. 제한 scene의 `DPR × page_scale` mapping이나 opt-in Root HTML Block fixture를 일반 HTML 출력 지원으로 해석하지 않는다.
- parser 제한의 기존 검증은 tree-construction fixtures, C API validation, JavaScript-only session 경계와 opt-in 실제 V8 document getter를 포함한다. [고정 HTML 직접 전달 Android 캡처](https://macstudio.tailed42f2.ts.net/spinon/internal/evidence/c04-root-html-document-environment-2026-10-17/android-api37-root-html-accessors.png) · [iOS 캡처](https://macstudio.tailed42f2.ts.net/spinon/internal/evidence/c04-root-html-document-environment-2026-10-17/ios-iphone17pro-root-html-accessors.png). 이전 opt-in bundle asset 경로는 [Android 캡처](https://macstudio.tailed42f2.ts.net/spinon/internal/evidence/c04-root-html-document-environment-2026-10-17/android-api37-root-html-asset.png)와 [iOS 캡처](https://macstudio.tailed42f2.ts.net/spinon/internal/evidence/c04-root-html-document-environment-2026-10-17/ios-iphone17pro-root-html-asset.png)에 있다. 기본 앱 경로는 [Android API 37 AVD와 iPhone 17 Pro/iOS 26.2 Simulator 실행 근거](./evidence/c04-12-root-html-default-app-2026-10-17/README.md), 환경 cascade는 [viewport·OS scheme runtime 실행 근거](./evidence/c04-12-root-html-runtime-environment-2026-10-17/README.md), Canvas 배경은 [Chromium 비교와 Android/iOS Simulator 실행 근거](./evidence/c04-12-root-canvas-color-scheme-2026-10-17/README.md)를 참조한다. Canvas는 native content root만 채우며 HTML layout·text·paint, page-scale transform, controls/system UI palette는 지원하지 않으므로 C04.12 완료 기준에 미달한다.
