확인한 결과
  • 기본 화면 실행은 Android 실기기·Android AVD·iOS Simulator에서 V8 평가, layout=ready, 10개 box 제출을 확인했습니다.
  • 별도 Android AVD matrix는 26/26 outcome을 확인했습니다. 21개 지원 장면은 준비됐고 5개 미지원 경계는 기대한 진단과 함께 거부됐습니다.
  • 지원 scene의 fixture node 64개 frame은 고정 Chrome reference와 최대 오차 0 CSS px였습니다. 허용치는 0.5 CSS px입니다.
  • Android API 37 AVD의 실제 SurfaceView를 PixelCopy로 읽었습니다. 21개 지원 scene과 22개 표본이 모두 일치했고 최대 channel error는 0이었습니다.
  • 여덟 `row`·`row-reverse`·`column`·`column-reverse` 및 order 조합은 Rust paint-rank, macOS WGPU, iOS Metal surface pixel에서 pinned Chrome 표본과 일치했습니다. iOS 실험은 8/8, channel tolerance 0입니다.
  • iOS Simulator와 Android API 37 AVD에서 C12.4 runtime session 0·1·2·4·8개를 누적 생성·해제하고 단계별 memory를 세 번씩 수집했습니다. 8 MiB/session은 worker stack 요청값이며 process memory와 구분합니다. 측정표와 원본 로그
  • reverse Flex paint는 Chrome 154의 관측을 따르는 제한 호환 예외입니다. W3C Flexbox Level 1 §4.3/§5.1 설명과 충돌하며 표준 적합성 주장이 아닙니다.
  • macOS headless WGPU readback 네 표본은 cyan, green, red, root background의 기대 RGBA와 정확히 일치합니다.
  • painter의 명시적 Vec::try_reserve capacity-growth 지점마다 실패를 주입해 stage별 오류를 확인했습니다. 실제 전역 allocator OOM을 재현한 실험은 아닙니다.
  • 합성 paint-context graph 50,000단계 깊이와 50,000개 형제 폭을 flatten하고 모든 NodeId 순서를 확인했습니다.
  • 실제 HostDocument→Stylo→Taffy→paint graph 128 nodes는 기본 test stack에서 통과하고 1,024 nodes는 32 MiB test stack에서 통과했습니다. 재현 조건은 깊은 그래프 실행 근거에 있습니다.
남은 검증
  • 고정 WPT 자동 후보 4개는 Chrome 154 runner에서 통과했고, 수동 후보 1개는 Chrome 화면으로 확인했습니다. Spinon의 WPT 적합성 판정은 아닙니다. 실행 요약
  • 측정은 Simulator/AVD에 한정합니다. iOS 실기기 memory, Android 실기기 RSS, worker thread별 stack commit은 미측정입니다.
  • Android AVD의 `VmSize`가 첫 runtime host 뒤 크게 증가하고 session 해제 후 일부 유지됐지만 `/proc/maps` 권한이 없어 mapping 원인을 특정하지 못했습니다. virtual size를 resident memory로 해석하지 않습니다.
  • 기본 test stack의 깊이 256 layout overflow 관측은 유지합니다. Android/iOS worker 8 MiB stack에서 1,024 성공·1,025 거부를 확인했습니다.
  • Android AVD의 ANGLE/SwiftShader 결과는 하드웨어 GPU 증거가 아닙니다. `Vec::try_reserve` 오류 주입은 전역 allocator OOM 복구를 보장하지 않습니다.
  • 고정 WPT 4개와 수동 후보 1개는 Chrome 154 기준 동작 확인이며 Spinon WPT 적합성 판정이 아닙니다.
  • 이 근거로 C12.4 또는 전체 CSS 지원을 완료 처리하지 않습니다.
