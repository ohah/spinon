# R09 · iOS 앱 배포·OTA 정책 검토 계획

- **상태:** 계획 검토·정책 조사 완료 · 구현·PR 변경 검토 완료
- **기준일:** 2026-10-16
- **상위 항목:** [구현 상태 대장 R09](../spec/STATUS.md#1-위험-검증)
- **변경 대상:** `docs/ota-design.md`, `spec/STATUS.md`, 날짜가 있는 조사 근거

## 목적과 범위

Apple App Store 심사 지침에서 V8의 원격 JavaScript 실행, CSS/리소스 OTA, 앱 기능 변경과 미니 앱 제공의 경계를 조사한다. 이 작업은 앱별 심사 승인이나 법적 적합성 보증을 내리지 않는다. OTA wire format·서명·키 운영·클라이언트 구현은 R15/D02/D04에 남긴다.

앱 바이너리와 함께 제공되는 일반 앱, 서버에서 JavaScript 소프트웨어를 제공하는 미니 앱형 앱을 같은 분류로 가정하지 않는다. Apple 지침에 CSS 변경을 직접 분류하는 문구가 있는지도 따로 확인한다. 제품 분류가 불명확한 경우 문서에 미정 범위로 남긴다. `2.5.2`에서 도출한 새 바이너리 제출 경로는 Spinon의 보수적 제품 gate 권고로 표현하고 Apple의 직접 명령으로 가장하지 않는다.

## 기준과 독립 oracle

- 기준 원본: Apple [App Store Review Guidelines](https://developer.apple.com/kr/app-store/review/guidelines/) 현재 본문.
- Agent Browser 확인일: 2026-10-16.
- 직접 대조할 절: `2.5.2`(기능을 추가하거나 변경하는 코드를 내려받아 설치·실행하는 제한과 교육용 앱 조건), `2.3.1(a)`(새 특징·기능·제품 변경의 심사 정보 공개), `4.7` 및 `4.7.1`–`4.7.5`(HTML5/JavaScript 기반을 포함한 비내장 소프트웨어 제공 조건).
- 저장소 기준: 현재 `docs/ota-design.md`, `spec/0004-runtime-build.md`, R09 설명을 같은 source 항목과 맞춘다.
- 독립 oracle: Apple의 규범 본문만 정책 요구의 근거로 사용한다. Spinon의 내부 설계는 정책 자체의 oracle로 사용하지 않는다.

## 조사 입력과 판정 기준

| 사례 | 확인할 판정 |
|---|---|
| 기존 앱의 원격 JavaScript가 새 기능을 추가하거나 기존 기능을 변경 | `2.5.2` 원문을 적용하고 일반 OTA 허용이라고 쓰지 않는다. 새 바이너리 제출은 Spinon의 보수적 권고임을 밝히고 Apple의 직접 요구와 구분한다. |
| 기존 기능에 대한 수정·오류 수정 | 정책 본문에 일반적인 버그 수정 예외가 명시되어 있는지 확인한다. 명시가 없으면 자동 허용 예외를 만들지 않는다. |
| CSS만 바꾸는 업데이트 | 지침이 CSS를 직접 분류하는지 확인한다. 직접 분류가 없으면 코드와 같다고 단정하거나 자동 면제라고 단정하지 않고, 기능 영향 판단은 보수적 해석으로 표시한다. |
| HTML5/JavaScript 소프트웨어를 별도 사용자 기능으로 제공 | 앱 자체가 `4.7` 분류에 해당하는지 구분하고, 해당할 때 `4.7.1`–`4.7.5`의 전체 요구를 요약한다. |
| 미니 앱 코드의 네이티브 API·권한·개인정보 사용 | `4.7.2`·`4.7.3`의 사전 허가·인스턴스별 동의를 확인한다. |
| 미니 앱 제공·심사 메타데이터 | `4.7.1`·`4.7.4`·`4.7.5`와 `2.3.1(a)`의 요구를 분리한다. |

완료 조건은 (1) 원문 절과 제품 설계 해석을 분리하고, (2) 원격 JS·CSS·콘텐츠·네이티브 변경을 같은 범주로 뭉개지 않으며, (3) 4.7을 모든 V8 앱에 대한 포괄 허가로 해석하지 않고, (4) 4.7 세부 요구와 심사 정보 공개를 빠짐없이 기록하고, (5) Apple의 앱별 판단·Spinon OTA 구현·스토어 승인을 완료로 주장하지 않는 것이다. 상태 대장에는 조사 완료만 기록하고 OTA 기능 구현은 미완료로 둔다.

### 계획 검토 판정

20개 관점은 정책 원문 범위, 두 앱 분류, 세부 요구, 구현/심사 구분, 시간에 따른 출처 변화를 서로 다른 조건으로 검토했다. 조사 결과에서 CSS 정책 분류나 개별 앱 적격성이 원문만으로 정해지지 않으면 이를 추론으로 표시하고 R09 범위를 넘어 확정하지 않는다.
