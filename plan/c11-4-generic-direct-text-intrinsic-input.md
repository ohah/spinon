# C11.4 direct element text intrinsic collector 최소 fixture 계획

**상위:** [C11.4 track sizing](./c11-4-grid-track-sizing.md) · [내부 계약 0059](../spec/internal/0059-c11-grid-layout.md) · [공식 상태](../spec/STATUS.md#c11-css-grid)

**상태 · 2026-10-26:** Chrome 156 여섯 장면과 독립 Ahem 기대값을 고정했다. direct element-text collector의 focused HostDocument/Stylo/C15 fixture test 9/9, `c11_4` 34/34, `c114` 19/19, runtime targeted Clippy, fmt가 통과했다([구현 test 관찰](../spec/internal/evidence/c11-4-generic-direct-text-intrinsic-precomparison-2026-10-26/implementation-test-observation-2026-10-26.md)). 기존 normal positive `generic-root-normal`을 FFI registry와 feature-gated Android/iOS matcher에 연결했다. FFI source test 1/1과 Android API 37 ARM64 AVD 및 iPhone 17 Pro/iOS 26.2 Simulator의 app build, scene summary, frame/trace assertions, draw/present와 screenshot 검증이 통과했다([runtime evidence](../spec/internal/evidence/c11-4-generic-direct-text-intrinsic-runtime-2026-10-26/README.md)). 이 app route는 한 canonical positive만 다룬다. 나머지 다섯 positive는 HostDocument tests, error/fallback controls는 Rust tests에 둔다. Screenshot은 glyph paint를 입증하지 않는다. 공식 C11.4 상태는 `72/213`으로 유지되며 C11.4 완료 checkbox는 미완료다.

## 현재 결손과 범위

[기존 C11.4 text fixture adapter](../crates/spinon-runtime/src/session/ua_cascade/runtime_layout/fixtures/c11_4_text.rs)는 전용 adapter를 먼저 시도하고 마지막에 root/item ID와 text literal을 `TEXT_CASES`와 대조한다. 새 root·text에서 computed style로 `ParagraphStyle`을 구성하는 scene-independent direct text 입력은 없다. 일반 entry `compute_runtime_block_flex_grid_track_sizing_style_layout`은 engine을 받지 않으며, text를 연결하는 fixture helper는 caller가 만든 `paragraph_styles`와 `TextLayoutEngine`을 인자로 받는다([현재 API](../crates/spinon-style-to-layout/src/projection.rs#L241), [text helper](../crates/spinon-style-to-layout/src/projection.rs#L477)).

이 PR 후보는 기존 special adapter와 legacy `TEXT_CASES`를 일괄 삭제하지 않는다. `prepare_c11_4_text`의 기존 scene-specific adapter dispatch를 모두 보존하고, 마지막 special adapter 뒤이며 기존 root-wide Text node count scan 시작 전(`pending = vec![root]`)에 제한된 generic collector를 넣는다. 허용된 direct element-text 입력을 content/style 기반으로 처리한다. 대상 바깥 구조는 `Ok(None)`으로 기존 one-text `TEXT_CASES` fallback에 넘긴다. generic candidate가 multiple/mixed source처럼 소유권을 부분 처리할 수 있는 입력은 명시 오류로 닫아 fallback하지 않는다. 여섯 고정 장면 외 임의 CSS·font·script 일반 지원을 주장하지 않는다. anonymous text grouping, nested Grid text, image+text 혼합, aspect-ratio text transfer, nonzero CSS `order`, `visibility:collapse`, 외국 namespace text, text paint는 이 최소 slice 밖이다.

여섯-scene Rust test는 별도 HostDocument root에서 collector·Stylo cascade·C15 helper를 호출하며 FFI/C0410 app route 자체를 실행하지 않는다. 이 계획은 app 경로에 canonical positive 하나만 추가한다. FFI scene ID와 DOM root ID는 둘 다 `generic-root-normal`; DOM item IDs는 기존 normal fixture 그대로 `generic-normal-a`와 `generic-normal-b`다. Collector 자체는 이 ID를 dispatch key로 사용하지 않는다. 다른 다섯 positive scene을 앱 allowlist로 확대하거나 negative controls를 app runtime으로 옮기지 않는다.

## 실제 runtime API와 source/style 매핑

구현은 새 public/product entry를 만들지 않고 현재 fixture 호출 흐름을 사용한다.

1. `runtime_layout.rs`는 `request.snapshot`, mount root, `ComputedStyleSnapshot styles`를 기존대로 만든다.
2. 기존 특수 adapter dispatch 뒤의 `fixtures::prepare_c11_4_text(&request.snapshot, root, &styles)`가 generic 후보를 모은다. 후보마다 `ComputedStyleSnapshot.elements`에서 `ComputedElementStyle.node_id == item.id()`인 style을 찾는다. `ComputedElementStyle.properties`의 computed CSS 값, typed `font_size_css_px`, `layout_position`, `ComputedStyleSnapshot::writing_style_for(item_id)`만 사용한다([style 자료형](../crates/spinon-style/src/stylo_dom/cascade/snapshot.rs#L500), [snapshot](../crates/spinon-style/src/stylo_dom/cascade/snapshot.rs#L576)). 누락되거나 중복된 owner/style는 오류다.
3. item `NodeId`를 key로 `BTreeMap<NodeId, ParagraphStyle>`을 만든다. `ParagraphStyle`의 실제 필드는 `font_family`, `font_size`, `line_height`, `line_height_is_normal`, `font_weight`, `font_style`, `white_space`, `word_break`, `direction`, `writing_mode`, `text_orientation`, `line_break`, `ligatures`다([자료형](../crates/spinon-text-layout/src/model.rs#L124)). 변환은 `root_html_text_paint/text.rs::paragraph_style`와 같은 node-specific typed conversion pattern을 따른다([선례](../crates/spinon-runtime/src/session/ua_cascade/runtime_layout/root_html_text_paint/text.rs#L15)); `text-align:start`, `overflow-wrap:normal`, `text-transform:none`, spacing/indent 기본값 등 `ParagraphStyle`에 없는 값을 먼저 확인하고 다른 값은 `node_id`와 property를 보존해 거부한다.
4. 이 fixture 전용 `C11_4TextInput`은 map과 Ahem `TextLayoutEngine`을 가진다. 현재 adapter와 같이 `TextLayoutEngine::new_without_system_fonts()`에 저장소 `AHEM` bytes를 `register_font("Ahem", AHEM)`로 등록하고 `prepare` 결과로 반환한다([현 adapter pattern](../crates/spinon-runtime/src/session/ua_cascade/runtime_layout/fixtures/c11_4_text.rs#L249)). 새 direct-text input은 현재 struct의 `two_axis_nested_grid=false`를 명시하고, runtime caller가 two-axis helper가 아닌 일반 `..._with_text_paragraphs` helper를 선택하는 경로여야 한다([현재 분기](../crates/spinon-runtime/src/session/ua_cascade/runtime_layout.rs#L579)). 일반 제품 engine이 아니며 시스템 fallback을 사용하지 않는다.
5. `runtime_layout.rs`가 기존 `compute_runtime_block_flex_grid_track_sizing_style_layout_with_text_paragraphs(&snapshot, root, styles.clone(), viewport, &input.paragraph_styles, &input.engine)` helper를 호출한다([호출부](../crates/spinon-runtime/src/session/ua_cascade/runtime_layout.rs#L570), [helper 계약](../crates/spinon-style-to-layout/src/projection.rs#L479)). 이는 `c11-4-grid-track-sizing-fixture-test` feature 안에서 `RuntimeBlockFlexGridTrackSizingV1` profile과 viewport 일치를 확인한다. Generic collector와 CSS→paragraph conversion도 이 opt-in fixture 경로 안에만 둔다.

CSS mapping은 다음으로 고정한다.

Chrome `fixture.html`을 Stylo author sheet로 그대로 재사용하지 않는다. 그 파일의 `@font-face`, `font`/`white-space` shorthand 및 `.fixed`의 `grid-column` 선언은 C11.4 track-sizing author allowlist 밖이다. Rust fixture는 같은 관측 computed values를 만드는 제한 longhand sheet를 사용하고 Ahem bytes는 `TextLayoutEngine`에 직접 등록한다. 두 item의 default grid auto-placement은 `[item-a,item-z]` DOM order와 두 명시 column을 그대로 첫째·둘째 column으로 배치하므로 explicit `grid-column`을 요구하지 않는다.

```css
.scene {
  display: grid;
  width: 100px;
  grid-template-columns: min-content max-content;
  grid-template-rows: auto;
  grid-auto-flow: row;
  column-gap: 10px;
  align-items: start;
  font-family: Ahem;
  font-size: 10px;
  font-weight: 400;
  line-height: 10px;
}
.item {
  display: block;
  position: static;
  font-family: inherit;
  font-size: inherit;
  font-weight: inherit;
  font-style: normal;
  line-height: inherit;
  white-space-collapse: collapse;
  text-wrap-mode: wrap;
  word-break: normal;
  overflow-wrap: normal;
}
.nowrap .item { text-wrap-mode: nowrap; }
.break-all .item,
.item.break-all { word-break: break-all; }
```

생성한 `ComputedStyleSnapshot`을 직접 `ComputedElementStyle` 입력으로 만들어 테스트하지 않는다. 각 scene의 Stylo view와 위 `StylesheetSource`에서 실제 `spinon_style::compute_runtime_block_flex_grid_track_sizing_cascade_with_stylesheets(view, author_stylesheets, viewport, style_revision)`를 호출한다. 그 결과의 item `properties`, `font_size_css_px`, `writing_style_for`가 JSON의 item computed values와 profile에서 지원하는 모든 값에 대해 일치하는지 먼저 검사한다. 차이가 있으면 text collector 실행/geometry 비교를 통과로 세지 않는다.

Collector를 호출하기 전에 scene root `ComputedElementStyle`도 실제 typed snapshot에서 검사한다. `grid_layout`은 `columns=[MinContent, MaxContent]`, `rows=[Auto]`, `auto_flow=Row`, `auto_rows=Auto`여야 하고, `layout_dimensions.width=LengthPx(100)`, `height=Auto`, `layout_spacing.column_gap=LengthPx(10)`, `properties["display"]="grid"`, `properties["align-items"]="start"`여야 한다. scene root `layout_spacing`의 margin·padding 네 면은 0이어야 한다. 이 검사는 `.fixed`의 `grid-column`을 제거한 Rust fixture가 browser 최종 DOM 순서대로 두 column을 채우는 데 필요한 row auto-placement 조건을 고정한다. browser JSON에는 root computed style serialization은 없고 root/item rect 및 track 크기만 있다. 따라서 root 값은 수정하지 않은 hashed `fixture.html`의 author input과 실제 Stylo typed result로 검사하며, `grid-reorder`의 같은 y 좌표와 item x 위치는 browser geometry 비교에서 별도로 확인한다. JSON만으로 browser root computed-style map까지 증명한다고 주장하지 않는다.

- `font-family:Ahem`, `font-size:10px`(typed `font_size_css_px`), `font-weight:400`, `font-style:normal`, `line-height:10px`이며 `ParagraphStyle.line_height_is_normal=false`다. `line-height:normal`은 이 profile에서 허용하지 않는다.
- `white-space-collapse:collapse`와 `text-wrap-mode:wrap|nowrap`를 각각 `WhiteSpaceMode::Normal|NoWrap`로 변환한다. `word-break:normal|break-all`, `direction:ltr`, `line-break:auto → LineBreakMode::Strict`, ligature 기본값 `Normal`을 사용한다. `writing_mode`/`text_orientation`은 string 추측이 아니라 `writing_style_for(item_id)` typed 결과가 `HorizontalTb`/`Mixed`인지 확인한다.
- `ParagraphStyle`이 표현하지 않는 `text-align` 등은 앞서 고정한 기본 computed 값만 허용한다. 이 slice의 문자열은 대문자 ASCII `A–Z`와 U+0020 space만 쓴다. `hyphens`, visibility 변형, SVG/MathML namespace, 비기본 ligature, 임의 script/font, aspect-ratio 축 전달, nonzero CSS `order`는 positive style contract 밖이다. `order`는 현재 computed properties에서 0인지 검사한다. 이 계획은 제한 StylesheetSource에서 허용 범위 밖 declaration이 일반적으로 거부된다는 동작을 주장하거나 그 동작에 negative acceptance를 걸지 않는다.

`ParagraphStyle.ligatures=Normal`은 이 slice의 고정 positive value다. 해당 property를 computed snapshot에 capture하거나 author allowlist를 넓히지 않는다. 미지원 declaration의 fail-closed negative는 stylesheet rule이 아니라 item의 inline `style` attribute로 구성한다. Stylo가 인식하는 `visibility:collapse`와 `font-variant-ligatures:none`은 `CssCascadeError::UnsupportedInlineAuthorProperty { node, property }`를 내야 한다. Stylo 0.22가 모르는 `hyphens:none`은 parser가 `UnknownProperty` diagnostic을 남기고 cascade snapshot을 반환하는 별도 parser 관찰이다. 이것을 C11.4 rejection error나 hyphens 계산 지원으로 해석하지 않으며 exact error control에 포함하지 않는다. Positive StylesheetSource에는 계획에 열거한 제한 longhand만 둔다.

## HostDocument fixture와 좌표 계약

Chrome HTML은 여섯 Grid를 한 문서에 세로로 둔다. Rust fixture는 각 scene을 **별도 `HostDocumentSnapshot` 하나로 구성하고 해당 Grid 요소를 mount root**로 쓴다. Stylo view는 runtime과 같은 `StyloDocumentView::new_html_runtime_mount_shared(Arc::new(snapshot.clone()), root)`로 만들며 `view.mount_root_element().handle() == root`를 확인한다([constructor](../crates/spinon-style/src/stylo_dom/document.rs#L162)). 이 view에는 selector/cascade용 synthetic html/body가 있지만 scene root만 layout helper에 넘긴다. scene이 root width/font를 직접 지정하고 helper가 root-relative layout을 계산하므로 synthetic body box를 geometry 입력에 넣지 않는다. 여섯 scene을 한 HostDocument로 합치거나 child Grid를 API root로 넘기지 않는다. CSS의 `.scene`와 `.item` 계산 style은 scene과 자식에 적용하고 viewport는 observation JSON과 같은 `1280×633 CSS px`, DPR 1로 둔다.

Rust builder는 browser fixture의 script를 실행하지 않는다. 각 scene 입력은 DOM tree와 computed style 값의 고정 builder로 만들며, CSS selector cascade가 동일해지도록 root `class`는 모든 장면에서 `scene`, `nowrap` scene에서는 `nowrap`, `break-all` scene에서는 `break-all`을 추가한다. item `class`는 `item`; `grid-reorder`의 `item-a`에만 `break-all`을 더한다. `.fixed`와 `grid-column` selector는 Rust sheet에 없으므로 class를 만들지 않는다. `grid-reorder`는 관측 JSON이 기록한 **최종** `childOrder=[item-a,item-z]`를 처음부터 생성한다. `item-a`는 `ABCD`/break-all, `item-z`는 `A BC`/normal이다. `grid-9x`는 변경된 root/item ID와 `A BCD`를 그대로 포함한다. class는 cascade input이며 scene ID/root ID/item ID/text literal은 collector dispatch key나 style mapping key가 아니다. 이 Rust builder는 HTML document parser의 적합성 근거가 아니다.

`LayoutFrame`은 계산 root 기준 절대 좌표다. 위 table은 browser JSON의 root/item/textRect에서 scene root `x,y`를 각각 빼고 기록했다. Rust scene별 mount root frame은 `(0,0)`이어야 하며 item frame을 이 local 좌표와 직접 비교한다. 최종 `TextLayoutSnapshot.lines`는 item-local `line_top`, `line_height`, `advance`를 비교한다. browser `Range.getClientRects()`는 각 rect의 item frame `x,y`를 빼서 line-local x/y/width/height와 대조한다. screenshot/device pixel은 이 assertion의 입력이 아니다.

이 section은 구현 입력 계약을 기록한다. 저장된 JSON은 계속 Chrome DOM observation이며 Rust `HostDocumentSnapshot`, computed snapshot 또는 runtime evidence가 아니다. 별도 HostDocument builder, 실제 Stylo cascade, collector, C11.4 text helper와 C15 layout을 연결한 local unit-test 결과는 [구현 test 관찰](../spec/internal/evidence/c11-4-generic-direct-text-intrinsic-precomparison-2026-10-26/implementation-test-observation-2026-10-26.md)로 분리한다. 이 test는 JSON 내용을 변경하거나 app/runtime/simulator 결과로 확대되지 않는다. 상세한 사전 비교 provenance는 [README](../spec/internal/evidence/c11-4-generic-direct-text-intrinsic-precomparison-2026-10-26/README.md#planned-rust-fixture-input) 참조.

## 최소 collector 허용 조건과 거부 조건

- Grid item은 HTML namespace의 direct element child이고, computed `display:block`, in-flow `position:static`, computed `order:0`이어야 한다. item 직속에 의미 있는 Text node가 정확히 하나 있어야 한다. 모든 positive text item을 DOM source order대로 모은다. item/node/root ID나 문자열로 분기하지 않는다.
- collapsible HTML whitespace-only Text child는 별도 item/source로 만들지 않는다. text 없는/길이 0인 일반 block sibling은 기존 box 경로로 둔다. 둘 이상의 의미 있는 Text node, descendant/anonymous text, replaced image+text 혼합, foreign namespace는 이 generic collector가 조용히 부분 수집하지 않고 typed 오류로 닫는다.
- six positive scene의 computed item box style은 `width/height/min-width/min-height:auto`, `max-width/max-height:none`, ratio 없음, zero margin/padding/border다. `max-width:auto`와 `max-height:auto`는 이 CSS input에서 유효하지 않으므로 쓰지 않는다. box constraint/ratio/edge를 추가하는 별도 slice는 여기서 지원한다고 주장하지 않는다. 기존 13개 `TEXT_CASES` fallback scene은 호환 범위로 유지한다. 이 계획은 13개 scene 각각의 runtime fallback 회귀 실행 결과를 주장하지 않으며, 그 범위를 새 collector의 aspect-ratio 또는 edge 지원 증거로 확대하지 않는다.
- 현재 special adapter dispatch 순서는 보존한다. generic collector는 여섯 positive scene 조건을 만족하면 scene ID 없이 처리한다. 대상 밖의 기존 단순 scene은 기존 fallback으로 유지하고, unknown non-matching root/content는 기존 명시 오류로 닫는다. 새 product CSS admission 또는 general HTML parser 경로는 추가하지 않는다.
- fallback과 candidate 판정은 구조로 나눈다. 기존 special dispatch 뒤 root의 computed `display`가 `grid`가 아니거나 기존 legacy one-item/one-text `TEXT_CASES` shape라면 collector는 `Ok(None)`으로 기존 one-text fallback 경로에 넘긴다. 이것은 fallback 경로를 선택한다는 뜻이지 성공을 보장하지 않는다. 기존 fallback은 root subtree의 의미 있는 Text node가 하나뿐이고, 그 Text node가 유일한 child인 HTML `div` item이 root의 유일한 child이며 root/item ID와 text가 `TEXT_CASES`에 맞고 기존 typed Grid/text style 검사도 통과할 때만 성공한다. 나머지는 기존 오류 또는 `None` 결과를 따른다. 반면 Grid root에 direct item 후보가 둘 이상 있고 그 아래 의미 있는 text가 하나라도 있으면 이 slice의 candidate다. Grid root 직속에 의미 있는 Text node가 있으면 익명 Grid text로 분류해 바로 `unsupported_c114_text_source`로 닫는다. positive candidate는 정확히 두 direct text-item candidate로 한정하며, 두 item 모두 HTML `display:block`/in-flow `position:static`이어야 하고 각각 의미 있는 direct Text child 정확히 하나만 가져야 한다. 두 개를 넘는 direct text-item candidate 또는 source ownership·namespace·mixed image/descendant shape 불일치는 `unsupported_c114_text_source`와 관련 node IDs로 거부한다. candidate의 paragraph property, `order`, item `width/height/min/max`, aspect ratio 또는 box edge가 허용값과 다르면 `unsupported_c114_text_style`와 item/property로 거부한다. root typed grid/style 값이 다르면 `unsupported_c114_text_grid_style`와 root/property로 거부한다. 이 세 오류는 fallback에 넘기지 않으며 부분 `C11_4TextInput`을 만들지 않는다. 어떠한 고정 scene ID/root ID/item ID/text literal도 후보 판정·스타일 mapping·거부 이유에 사용하지 않는다. |

## Stage A 입력 acceptance와 단계

1. 고정 Chrome evidence의 hash, independent math, final child order를 사용한다. 이 계획 작성 중 browser 재실행은 하지 않았다.
2. Rust test builder를 추가해 위의 여섯 scene마다 Grid root를 mount root로 가진 HostDocumentSnapshot을 만들고 `StyloDocumentView::new_html_runtime_mount_shared(Arc::new(snapshot.clone()), root)`로 view를 구성한다. 위 제한 longhand `StylesheetSource`와 실제 C11.4 Stylo cascade API로 computed-style snapshot을 얻고 그 style revision/viewport를 layout input과 일치시킨다. builder 자체 입력은 이 계획 표의 content/final order만 사용하며 scene ID 기반 dispatch를 구현하지 않는다.
3. `prepare_c11_4_text`의 기존 special dispatch 뒤, 현재 generic `pending = vec![root]` text-count scan 전에 generic direct-item collector와 computed-style→`ParagraphStyle` converter를 둔다. `Ok(None)`만 legacy one-text scan/`TEXT_CASES` fallback으로 이어지고, source ownership이 모호한 candidate error는 fallback하지 않는다. 만들어진 map과 Ahem engine은 기존 `C11_4TextInput`와 C11.4 text helper API를 그대로 통과한다.
4. helper 반환형은 `StyleLayoutOutput`이며 그 안에 실제 `LayoutOutput`이 `output.layout`로 들어 있다([helper 반환형](../crates/spinon-style-to-layout/src/projection.rs#L477), [wrapper](../crates/spinon-style-to-layout/src/projection.rs#L52)). `output.layout.grid_item_intrinsic_inputs`에서 scene당 정확히 두 item을 확인한다. 각 entry의 `grid_container`, `node`, `source_order`, `revision`, `source=Text`, `TextIntrinsicInlineSizes.font_registry_revision()`을 고정한다. 익명 token은 직접 읽을 수 없으므로 `contribution_input()`이 보존한 `TextIntrinsicInlineSizes`와 원본 sizes를 `uses_same_font_registry_revision()`으로 비교해 raw→contribution identity 보존을 확인한다. 동일 `&TextLayoutEngine`이 intrinsic과 definite layout에 전달되는 것은 기존 helper 경로의 계약이다([helper](../crates/spinon-style-to-layout/src/projection.rs#L479), [intrinsic engine 호출](../crates/spinon-layout/src/calc_tree/text.rs#L316)). `output.layout.intrinsic_measurements` 안의 `LayoutIntrinsicMeasurementSource::Text`와 `output.layout.text_layouts[&item_id]`의 최종 `TextLayoutSnapshot`은 공개 numeric font registry revision으로 비교한다. opaque token을 서로 다른 result type 사이에서 비교한다고 주장하지 않는다. Element owner의 단락인 이 입력에서 `text_sources`는 anonymous Grid text 전용이므로 비어 있어야 한다. 실제 Text NodeId와 원문은 `output.layout.text_layouts[&item_id].input.sources[0].node/text`에서 확인한다. 특히 `grid-ws`는 원문 " A  BC "가 그대로 들어가고 CSS collapse는 `ParagraphStyle.white_space`가 text engine에 적용하게 한다. 이 raw source entry를 final CSS contribution으로 부르지 않는다.
5. `output.layout.grid_item_intrinsic_inputs` 각 entry의 `contribution_input()`에서 위 oracle 표의 `width.min_content/max_content`, `height.min_content/max_content`, `width.preferred_size=Auto`, `height.preferred_size=Auto`를 typed 값으로 대조한다. `min_size/max_size`와 zero edges도 함께 기록한다. 이 여섯 case에서 text heights는 각각의 min/max-content wrapping 결과이며 B단계 track stage의 완료 주장이 아니다.
6. `output.layout.intrinsic_measurements`의 text probe (`available_space=MinContent|MaxContent` 및 revision/source)와 `output.layout.text_layouts[&item_id]`의 최종 C15 snapshot을 별도로 비교한다. Snapshot의 owner는 Grid item element, `input.sources`는 정확한 direct Text child 하나, revision은 `output.layout.revision`과 같아야 한다. `output.layout.frames[&item_id]`의 content width(이 corpus는 zero edge라 frame width)는 `output.layout.text_layouts[&item_id].layout.available_width`와 같아야 하며 `output.layout.text_layouts[&item_id].layout.width/height`, 줄 수·line advance·line height가 table/normalized Range rect에 맞아야 한다. Callback의 호출 순서는 고정하지 않는다.
7. `grid-9x` ID/content 변경 및 `grid-reorder` 최종 child order/style 쌍으로 scene/root/item text mapping이 ID에 의존하지 않는지 확인한다. Negative control은 두 의미 있는 Text node, Grid 직속 anonymous Text, descendant text, mixed image/text, non-HTML namespace, nonzero `order`, `display:flex`, 비기본 paragraph-only CSS, item aspect ratio/min/max/edge, font registry/asset mismatch와 stale source/style revision을 포함한다. candidate 거부는 성공한 `StyleLayoutOutput` 또는 그 안의 `output.layout`을 반환하지 않는다. 미지원 author property의 rejection control은 별도 candidate의 inline declaration으로 만든다. Stylo가 인식하는 `visibility:collapse`와 `font-variant-ligatures:none` 각각에 대해 `compute_runtime_block_flex_grid_track_sizing_cascade_with_stylesheets`가 snapshot을 반환하기 전에 item node와 exact property가 일치하는 `CssCascadeError::UnsupportedInlineAuthorProperty`를 내야 한다. 해당 error의 inline preflight 경계는 [`runtime_grid.rs`](../crates/spinon-style/src/stylo_dom/cascade/runtime_grid.rs#L297)와 [`runtime_layout.rs`](../crates/spinon-style/src/stylo_dom/cascade/runtime_layout.rs#L392)에 있다. 기존 C11.4 inline preflight의 같은 error variant는 [`orthogonal_writing_mode.rs`](../crates/spinon-style/src/stylo_dom/cascade/runtime_grid_tests/orthogonal_writing_mode.rs#L75)의 `text-orientation` control로 고정돼 있다. 별도의 `hyphens:none` probe는 Stylo 0.22가 property를 인식하지 못해 `UnknownProperty` diagnostic과 cascade snapshot을 반환하는지 기록하며, C11.4 rejection control이나 layout 지원 assertion이 아니다. 두 인식된 property control은 cascade error만 검사하며 ParagraphStyle 수집, intrinsic input, `StyleLayoutOutput`/`output.layout`/frame/trace가 생성되지 않아야 한다. 제한 stylesheet 안의 미지원 declaration rejection은 이 계획에서 주장하거나 검증하지 않는다. 이 통제들은 rejection-only이며 이 slice가 visibility, hyphens, ligature, ratio 또는 edge 동작을 지원한다고 주장하지 않는다.
8. 기존 special adapter order와 `TEXT_CASES` 13개 case table을 보존한다. Test split 뒤 focused generic tests와 관련 C11.4 regressions를 다시 실행한다. 현재 9/9 generic evidence는 legacy case table 고유성 검사와 generic one-item fallback selection control만 포함하며, 13개 legacy scene 각각의 runtime fallback 성공을 입증하지 않는다. 별도 per-scene regression이 실제 추가·실행되지 않는 한 13개 모두 runtime-tested라고 보고하지 않는다.
9. App-visible FFI/native scope는 `generic-root-normal` 하나로 한정한다. FFI scene source, Android/iOS scene ID allowlists, node frame expectations, text intrinsic/result and trace matchers가 기존 normal positive IDs/source/value를 그대로 연결한다. 다른 다섯 positive scenes는 HostDocument tests only, error/fallback negatives는 Rust tests only다. 이 app bridge는 제품 CSS admission이나 text paint support를 추가하지 않는다.
10. Android API 37 ARM64 AVD/iOS 26.2 Simulator에서 등록된 canonical scene만 실행해 source fingerprint, build/install app artifact, `status=0`/`layout=ready`/`boxes=3`, exact root/item frames, two direct Text intrinsic inputs, revision, contribution/final track trace, draw/present와 screenshot evidence를 수집한다. APK/app binary hash를 source revision과 함께 기록한다. Screenshot은 simulator UI evidence만이며 glyph paint/pixel equality를 증명하지 않는다. `runtime_text_count`/glyph draw가 0이면 글리프 paint로 해석하지 않는다.
11. Artifact boundary는 별도 후행 gate다. 기본/product와 fixture-test 산출물을 구별하고 project rule의 positive/negative control을 연결한다. 정적 archive 검사만 한 경우 final APK/IPA에서 fixture 제외를 주장하지 않는다.
12. 구현 후 새 실패 관점 20개와 PR diff 별도 30관점으로 검토한다. Agent Browser를 추가 실행하는 경우 해당 isolated session을 종료하고 inactive/process 상태를 확인한다.
13. 공식 상태 및 roadmap은 실제 merge 이후 연결하되 C11.4/C11 전체 완료 checkbox는 그대로 둔다.

## 완료 판정과 명시적 후속 범위

여섯 Chrome scene의 collector/source/style/C15 positive와 Rust-only negative controls는 HostDocument tests로 확인했다. Generic evidence의 legacy one-item fallback selection control과 `TEXT_CASES` matrix 고유성 검사는 13개 legacy scene 각각의 runtime fallback 실행을 입증하지 않는다. `generic-root-normal`은 FFI, Android/iOS feature-gated app route와 두 Simulator에서 검증했다. 최종 runtime trace는 `layoutInputRevision.intrinsicSize=0`을 출력했으며 matcher는 HostDocument source와 유효한 nonnegative revision 값을 확인한다. Matcher는 outer collapsed gutters, 반복 Columns query 및 definite-column-width Rows contribution도 대조한다. APK/app bundle과 screenshot 해시는 [runtime evidence](../spec/internal/evidence/c11-4-generic-direct-text-intrinsic-runtime-2026-10-26/README.md)에 기록한다. 이 한 장면의 runtime 검증은 전체 Stage A 완료나 13개 legacy fallback 실행을 뜻하지 않는다. narrowed contract의 독립 targeted recheck는 [별도 report](./c11-4-generic-direct-text-intrinsic-input-contract-recheck-2026-10-26.md)에서 4/4 PASS를 받았다. 전체 Stage A 완료도 아니다.

현재 검증은 fixture-test Debug APK/iOS Simulator app의 build와 설치·실행만 포함하며 Release artifact, product CSS admission 또는 final product APK/IPA의 fixture exclusion을 입증하지 않는다. 제품 CSS admission, `hyphens`/visibility variants, nonzero `order`, aspect-ratio/box-edge text transfer, source range의 전 범위 UTF offset 변환, HTML parser와 script 실행, 일반 text paint, Stage B/C/D, WPT 및 전체 C11.4는 별도 범위다. 공식 C11.4 상태 `72/213`과 완료 checkbox를 변경하지 않는다.
