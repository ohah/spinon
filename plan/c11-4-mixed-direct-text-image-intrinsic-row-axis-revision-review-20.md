## 판정

기본 정렬값 Chrome observation은 네 scene 모두 item computed `align-self:auto`·`justify-self:auto`와 기존 geometry `[50,24]` columns, 20px row, text `50×20`, image `24×16`을 기록한다. HTML·JSON·PNG hash는 사전 비교 README와 일치한다. 이는 Chrome 관찰이며 Spinon runtime 근거가 아니다. 계획의 runtime assertion gap은 source commit `0af34026`의 [style.rs:26-30](../crates/spinon-runtime/src/session/ua_cascade/runtime_layout/fixtures/c11_4_mixed/style.rs) root `justify-items:normal` 확인과 [style.rs:130-139](../crates/spinon-runtime/src/session/ua_cascade/runtime_layout/fixtures/c11_4_mixed/style.rs) row item `auto/auto` 확인으로 닫혔다.

최종 source commit `0af34026039f11c8f354856b34bdef12f8fd7878`에서 Android API 37 ARM64 16 KB AVD는 **4/4**, iPhone 17 Pro/iOS 26.2 Simulator는 별도로 **4/4** scene을 통과했다. 두 결과는 합산하지 않는다. Android run 뒤 AVD는 PID 없음/Launcher이고, 대상 iOS Simulator는 Shutdown 상태다. 저장 screenshots는 layout/box 배치 근거이며 glyph/PNG pixel equality 증거가 아니다.

두 run manifest의 commit/tree 및 9개 source-file SHA-256은 일치한다(aggregate `7e1d93fc…9652b1fb`). 다만 Android와 iOS의 tracked-diff SHA는 각각 `b878ee10…363a805d`, `b7c748de…e56db4c`로 다르며 tracked dirty paths는 두 run에서 동일한 evidence 문서 3개다. 그러므로 code-source identity는 같은 9개 hash로 확인되지만 evidence 문서 snapshot hash는 동일하지 않다는 provenance 한계를 유지한다. 앞선 `d83` 실행이나 수정 전 authored-alignment 입력의 0/4 실패는 최종 source 성공 수에 포함하지 않는다. 이 제한 slice가 C11.4 전체를 완료하지 않으며 공식 완료 수 `72/213`도 바꾸지 않는다.
