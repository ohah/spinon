## 로드맵 순서와 완료 범위

C09.4 shrink-to-fit은 C12·C14·C15·C26의 intrinsic/formatting 선행 작업을 기다린다. C10의 남은 텍스트 baseline과 자동 최소 크기도 C14·C15·C17에 의존한다. C11은 이 작업들을 완료로 가장하지 않고, definite size의 빈 요소부터 시작해 Grid 자체를 독립 구현한다. S02는 아직 부분 구현이므로 Grid 추가만으로 S02를 완료하지 않는다.

상태 대장의 X09는 C11과 동일한 Grid 구현 업무로 읽힐 수 있다. 구현 소유자는 C11 하나로 둔다. X09는 C11 결과를 Flex·텍스트 측정·적합성 묶음에서 교차 검증하는 추적 항목으로 유지하며 C11의 선행 조건이나 별도 중복 구현으로 취급하지 않는다. X16도 공통 적합성 자동화 작업이며 C11.1을 막지 않는다. C11 fixture와 실제 지원 범위는 나중에 X09/X16에 편입한다.

## 현재 구현 경계와 설계 결정

- 현재 C11.1 내부 Rust 경로는 `HostDocumentSnapshot`·같은 mount-root의 `StyloDocumentView` → `RuntimeBlockFlexGridV1` computed cascade → typed `ComputedCssGridLayout` → 엔진 중립 `GridContainerInput` → 기존 Taffy custom tree의 Grid dispatch까지 연결한다. adapter는 view와 snapshot 및 mount root 일치, document/style/environment revision을 확인한다. 별도의 제한 fixture 진입점은 Android/iOS 앱의 V8 runtime host와 FFI에 연결되어 같은 Rust 경로를 WGPU surface까지 실행한다. 이는 앱 개발자가 호출하는 공개 CSS/API나 전체 Grid 지원이 아니다.
- 잠긴 Taffy `0.14.0`의 `grid` feature와 `LayoutDisplay::Grid`를 사용한다. `CalcLayoutTree`는 custom tree에서 `Block`/`Flex`/`Grid`를 직접 dispatch하고 엔진 중립 Grid 입력을 사용한다. Taffy의 high-level tree로 바꿔 기존 CSS math handle·revision·positioning adapter를 우회하지 않는다. `CompactTaffyStyle`은 profile에서 쓰는 Taffy trait 필드만 보관한다.
- Taffy의 CSS 문자열 파서를 입력 원본으로 삼지 않는다. Stylo typed computed value에서 엔진 중립 track 값으로 검증 변환한 뒤 Taffy 0.14.0 Grid algorithm에 넘긴다. 단계별 unsupported 값은 node·property·value가 있는 오류를 반환한다. 지금 구현한 값은 definite `px`, percentage, 양의 유한 `fr`와 row auto-flow다. named line·area·repeat·`auto`·`minmax()`·`fit-content()`·calc track·placement 등은 지원하지 않는다.
- Taffy `grid` feature는 모든 `taffy::Style`에 named line·area·auto-track 저장 필드를 추가한다. 기존 전체 `Style`을 계산 트리 노드가 보유하면 macOS debug workspace에서 8 MiB worker의 depth 1,024 fixture가 stack overflow를 일으켰다. custom-tree trait가 실제로 쓰는 값만 담는 `CompactTaffyStyle` projection을 추가했고, 전체 Grid 스타일보다 작다는 검사와 optimized-profile 8 MiB·depth 1,024 runtime 시험을 통과했다. 현재 소스에서는 이 worker-depth test를 Debug에서 의도적으로 건너뛰며, Debug workspace 통과를 1,024-depth 검증으로 해석하지 않는다. [현재 소스 run-08](../spec/internal/evidence/c12-4-follow-up-verification-2026-10-12/current-source-rerun-20261012-08/README.md)와 [역사적 실행 기록의 후속 경계](../spec/internal/evidence/c11-grid-layout-core-validation-2026-10-12/README.md)를 본다. 16 MiB 임시 실험 변경은 되돌렸다. 다음 단계에서 Taffy trait 사용 범위가 늘면 compact projection도 함께 확장하고 크기·깊이 회귀를 유지한다.
- C11 단계별로 새 runtime `ComputedStyleProfile`을 분리한다. C04/C08/C09/C10/C12의 기존 profile에 새 성공 의미를 암묵적으로 추가하지 않는다. Grid를 포함한 Block/Flex/Grid 혼합 장면은 하나의 동일한 HostDocument·style·environment revision snapshot으로 계산한다.
- 기존 source tree, DOM 순서, 접근성 순서는 유지한다. Grid auto-placement는 CSS `order` 적용 시 order-modified order를 사용할 수 있지만 HostDocument child vector를 재정렬하지 않는다. C11.1은 `order:0`만 허용하고 비기본 order는 C11.6 교차 계약까지 fail-closed한다.
- C11.1의 트랙은 명시적 definite 크기만 다룬다. `fr` 분배 전에 gap을 제외하고, percentage는 해당 축의 definite content size를 기준으로 한다. indefinite axis, auto/min-content/max-content, span placement, implicit track은 이 단계에서 거부한다. Taffy의 자동 fallback이나 초기값으로 대체하지 않는다.
- Grid item의 fixed width·height와 빈 element box를 이용해 C14/C15의 intrinsic measurement 부재를 분리한다. anonymous grid item, text/replaced item, inline formatting, nested formatting context는 각 단계에서 입력을 고정하거나 실패 진단을 검증한다.
- Grid item의 visual placement와 paint order는 서로 다른 결과다. C11.1 auto-placement는 source order를 보존하며, C11.2의 overlap·`order`는 C12 stacking/painter와 분리해 검증한다. CSS 위치 지정 Grid item의 grid-area containing block은 C12 owner 변경 없이는 지원했다고 하지 않는다.
- 트랙 수·반복 확장은 임의의 새 상한으로 잘라 성공시키지 않는다. `origin/main`의 Taffy `0.14.0`과 현재 후보의 vendored Taffy `0.15.0`은 축별 10,000 explicit-track 경계에서 더 큰 Grid를 clamp한다. C11.4 후보는 `spinon-layout`의 모든 profile을 0.15.0으로 전환하므로 C11.1~C11.3 경로도 회귀 확인 대상이다. 현재 adapter는 경계 초과를 Taffy에 넘기지 않고 전체 계산을 `GridTrackLimitExceeded`로 거부한다. 이는 구현 제한이며 Chrome 호환 동작이나 CSS 적합성을 주장하지 않는다. W3C Grid Level 1은 UA 정의 한계와 바깥 line의 clamp를 허용하므로, 그 이상을 지원 범위에 넣으려면 Chrome 고정 입력으로 clamp 동작을 비교하고 Taffy 경계와 일치시키는 별도 단계가 필요하다. Spinon adapter가 소유한 확장·출력 buffer에는 `try_reserve`, checked index math, 기존 HostDocument quota와 명시적 오류를 적용한다. vendored Taffy 내부 Grid working buffer의 일부는 `reserve`/`with_capacity`를 사용하므로 이 경계 밖 allocator failure의 전역 복구를 보장하지 않는다.
- `display:none` subtree는 Grid item 수집과 track sizing에서 제외하고, 새 계산 실패 시 이전 scene을 새 revision으로 재사용하지 않는다. 스타일, child insertion/removal, viewport, track definition의 각각의 revision 변화에 stale snapshot 거부를 확인한다.

내부 경계는 [0059 Grid layout 계약](../spec/internal/0059-c11-grid-layout.md)에 둔다. 이는 앱 작성자가 사용하는 공개 CSS 지원 명세가 아니다. R01의 공개 범위 결정을 대신하지 않으며 출시 전 숫자 버전 `0.1.0`을 유지한다.

## 기준 구현과 fixture

- **규범 기준:** [CSS Grid Layout Module Level 1 · 2025-03-26 CRD](https://www.w3.org/TR/2025/CRD-css-grid-1-20250326/). 이 문서는 Candidate Recommendation Draft이며 구현 동작의 유일한 oracle로 쓰지 않는다. 불명확하거나 다른 구현 사례는 고정 Chromium 결과와 함께 기록한다.
- **계산 후보:** 저장소 `Cargo.lock`의 Taffy `0.14.0`; Grid feature와 `compute_grid_layout` custom tree interface를 고정한다. Taffy 결과만으로 CSS 적합성 판정을 하지 않는다.
- **브라우저 oracle:** Chromium `154.0.8037.98`, revision `b859317bf11f6be47f9b7799ec690a0a42a1fb33`, macOS arm64. 실행 파일·fixture·capture script·CSS 입력 SHA-256을 저장한다. 기준이 바뀌면 reference를 조용히 덮어쓰지 않고 새 ID를 만든다.
- **WPT 교차표:** upstream WPT commit `c999c58338ee1d223df5ad62e48be1202ced0d37`에 경로를 고정한다.
